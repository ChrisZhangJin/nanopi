# nanopi v0.12.0

One vocabulary for hook events, honest session payloads, a plugin
capability surface that lets extensions *do* things rather than only see
them, hot-reloadable extensions, and a long list of fixes on top of
v0.11.0's tool-execution and WASM-extension work.

v0.11.0 was closed but never released on its own, so everything in it is
also new to anyone upgrading from v0.10 — its sections are kept below.

## Highlights

### One vocabulary for the eleven events

nanopi's hooks used to mix two naming schemes: four events borrowed Claude
Code's own names (`pre_tool_use`, `post_tool_use`, `user_prompt_submit`,
`session_end`), while the other seven already used PI's names
(`before_agent_start`, `turn_start`, `turn_end`, `message_end`,
`session_start`, `session_before_compact`, `session_compact`). v0.12 finishes
the migration: the four Claude-Code-named events are renamed to PI's names,
so every hook key in `[[hooks.*]]` — and every `NANOPI_EVENT` value a hook
script sees on stdin — now speaks one vocabulary.

|            old key       |          new key         |
|---------------------------|---------------------------|
| `pre_tool_use`             | `tool_execution_start`     |
| `post_tool_use`            | `tool_execution_end`       |
| `user_prompt_submit`       | `input`                    |
| `session_end`              | `session_shutdown`         |

There is no alias and no deprecation window: a config using one of the
left-hand keys fails to load, and the error names the right-hand
replacement so the fix is a one-line edit.

### Steer / follow-up injection

Mid-stream typing steers the running turn; queued follow-ups auto-start the
next one.

### WASM extensions

Behind `--features wasm` (`src/wasm/`). Components declared in
`[[extensions]]` are compiled, instantiated, and their exported tools
registered alongside the built-ins. Capabilities: `host-log`, `host-fs-read`
(read-only, cwd-confined, symlink-aware), `host-http-get` (gated on
`allow_network`, then a deny-by-default host-matching `url_allowlist`; 10s
timeout, 1 MiB body cap, redirects not followed).

### Plugin slash commands

A component may export `list-commands` / `execute-command` from a second WIT
world, `extension-commands`, and its commands appear in the `/` palette
tagged with the plugin's name. A command returns an action rather than
calling back into the host, so the import list stays at three:
`{"print"}` writes to scrollback (never seen by the model),
`{"send_user_message"}` starts or steers a turn (always echoed verbatim
first), `{"error"}` is shown only to the user. Collisions are refused, never
renamed. Plugins load at startup, on `/new`, `/resume`, `/fork`, `/import`
— and, as of this release, on `/reload` too (see below).

### The Pi lifecycle hooks

Eleven hook events cover the full agent lifecycle: `before_agent_start`,
`turn_start`, `turn_end`, `message_end`, `tool_execution_start`,
`tool_execution_end`, `input`, `session_start`, `session_shutdown`,
`session_before_compact`, `session_compact`.

### WASM plugins can watch lifecycle events

A third, opt-in WIT world, `extension-events`, adds `list-events` /
`handle-event` so a plugin can observe (never veto or transform) the same
eleven lifecycle events shell hooks already see. Delivery requires **two
lists to agree** — the plugin's own `list-events` export AND the config's
`[[extensions]].events` grant; either alone delivers nothing. Payloads are
byte-identical to what a shell hook receives on stdin for the same event.
Guest handlers get a 2s epoch budget (vs 30s for tool calls) and delivery is
drop-on-busy rather than blocking, so a plugin mid-tool-call never stalls an
emit. `/tools` gained a "Watching events" section listing every subscribed
plugin, so the capability is never invisible.

### `tool_execution_end` can rewrite results

Not just observe them — a hook's stdout can transform the tool's result
before it reaches the model. (Named `post_tool_use` prior to this release.)

### Configurable tool exec mode

`tool_exec_mode = "parallel" | "sequential"` (`src/config.rs`). In parallel
mode, `edit` and `write` calls targeting the same file are still detected by
resolved path and serialized in emission order; `sequential` serializes the
entire batch, useful when the model drives shell-based rewrites of the same
files.

### `write`/`edit` confined to the working directory

Paths are canonicalized before any write, so `../` and outward-pointing
symlinks are refused.

### Inlined `<think>` blocks render as thinking

`<think>…</think>` isn't an OpenAI wire feature — it's a model-level
convention (R1 and its distills, QwQ, GLM, and others) that shows up
through *any* OpenAI-compatible endpoint: ollama, vLLM, DeepSeek direct,
gateways. Some lift it into a separate field; many pass it straight
through in the reply text. nanopi now recognizes a **leading** `<think>`
block — one where nothing but whitespace precedes the opener — even when
a delta splits the tag mid-stream, and renders the enclosed text as
dim-italic thinking instead of ordinary reply text. The reasoning also
stops entering the context, the session transcript, and the
`-p --output json` envelope, matching how the Anthropic-native wire
already handles reasoning. This is on by default for every vendor on the
OpenAI wire, not a two-vendor allowlist — position, not vendor identity,
decides what's reasoning. A `<think>` appearing after any other text
(mentioned in an explanation, quoted in a code fence, or a second block
after the first closed) is left as literal text. `inline_think_tags =
true | false` in `config.toml` is the escape hatch: `false` disables the
splitter entirely, even for a leading block. Residual failure mode: a
model whose reasoning block genuinely arrives after some other text
degrades to the old plain-text rendering — the position rule can't
distinguish that from a model discussing the tag.

### What a plugin may DO, not just what it may see

Watching events told a plugin what happened; it had no way to act on it.
v0.12 adds a capability surface in five stages, every one of them
deny-by-default and named in `[[extensions]]`. A grant that is absent is
a capability the plugin does not have, and `/tools` grew a **Plugin
grants** row so the set is never invisible — a plugin with nothing
granted still gets a row, reading `no grants`, because "installed and
powerless" and "not installed" must not look the same.

| grant | capability |
|---|---|
| `allow_store` | `host-store-get` / `host-store-set` — a keyed, quota-bounded, crash-safe store, one file per plugin, surviving restarts |
| `allow_context` | `host-set-context` — contribute text to the model's system prompt, attributed to the plugin |
| `allow_tools = [...]` | `host-call-tool` — call the named built-in tools, per tool, not wholesale |
| `allow_send_message` | `host-send-user-message` — start or steer a turn |

`host-notify` needs no grant: it is attributed and rate-limited output to
scrollback, and a plugin that could already write tool results could
already say things.

Three of these have a failure mode worth naming:

- **Context contributions are disclosed, not silent.** Text a plugin
  injects into the system prompt is attributed to it, so a reader of
  `/export` or the transcript can tell which extension put it there.
- **`host-call-tool` carries a `ToolCallOrigin`.** A tool call made by a
  plugin is not indistinguishable from one the model asked for; the
  origin travels with it.
- **`host-send-user-message` has a loop guard and a per-session
  budget.** The point of the cap is that a plugin cannot spend the
  user's money in a loop, and it deliberately survives `/reload` — see
  below.

### `/reload` now reloads `[[extensions]]`

For two releases `/reload` re-read skills and hooks but deliberately
skipped `[[extensions]]`, and said so. It no longer skips them. Editing a
grant and running `/reload` takes effect immediately, with no restart.

The mechanism is built around the failure cases rather than the happy
path:

- **Load before unregister, so a broken edit costs nothing.** A plugin
  whose `.wasm` no longer compiles or instantiates never becomes live,
  so its *previous* instance stays live and its tools stay callable. The
  report line names the failure instead of leaving you to notice. The
  alternative — ending up with neither — is strictly worse: you asked to
  pick up an edit, and the edit not compiling should not also take away
  the plugin that was working a second ago.
- **A call in flight when the swap lands is refused in-band**, and
  there are two different wordings on purpose. A call refused *before*
  entering the guest says it "was refused rather than run against the
  instance it was loaded from". A call that had *already entered* says
  the plugin "was replaced by /reload WHILE this call was running", that
  the result is discarded — and that **any side effects it already had
  stand**. Reporting a replaced instance's result as the new plugin's
  would be exactly the silent lie the mechanism exists to prevent.
- **Never "extensions reloaded" on its own.** A reload that claims more
  than it did is worse than one that admits a gap, so a failure appears
  in the report line itself.

State across a reload is decided per kind, because "survives a trap"
does not settle it — a reload is a user action, not a guest fault:

| state | across `/reload` |
|---|---|
| `host-store` files | **survive** — they are persistence across restarts; wiping them would make `/reload` destructive by surprise |
| `plugin_send` loop guard + spent budget | **survive** — otherwise the cap would be resettable by the very plugin that could ask the model to suggest a reload |
| `plugin_context` contribution, plugin still loaded **with** `allow_context` | **survives** |
| …same contribution otherwise (plugin removed, or reloaded without the grant) | **dropped**, and the report line names every drop — otherwise text attributed to an extension would sit in the system prompt with nothing able to retract it short of a restart |

Grants themselves are not migrated and cannot be: the new instance is
built from the config now on disk, so `allow_tools = ["read"]` becoming
`["bash"]` simply *is* the new bridge's gate set.

### `message_end` carries the assistant's reply

Previously `message_end`'s `arguments` held `{turn_count,
response_length}` — a number. A plugin could see what the user said
(`input`) and every tool result (`tool_execution_end`) but never what
the model said, so "remember the user's preference" was possible and
"remember the conclusion" was not. The payload now has four fields:
`turn_count`, `response_length`, `response`, `response_truncated`.

Two deliberate choices:

- **`response_length` keeps its old meaning** — the byte length of the
  *whole* reply, never of the truncated copy. A script reading it today
  reads the same number after upgrading.
- **Truncation announces itself three ways** at the 16 KiB cap:
  `response_truncated: true`, a `response_length` larger than
  `response`, and an in-band `[nanopi: response truncated, N of M
  bytes]` marker appended to the text. The in-band marker is the one
  that matters — a consumer that only reads `response`, which is the
  obvious thing to do, must not be able to draw a conclusion from half a
  sentence without seeing that the sentence was cut.

This payload is shared by shell hooks and WASM plugins, byte-identical,
so it is a **behaviour change for existing `[[hooks.message_end]]`
scripts** — see Compatibility.

### Per-tool `executionMode`, and `bash` declares itself sequential

A tool now declares its own execution mode, sitting between the global
`tool_exec_mode` and a new per-tool override:

```toml
[tool_exec_overrides]
bash = "parallel"     # I know what my commands touch
read = "sequential"   # belt and braces
```

Precedence: the global mode picks the batching strategy, a `Sequential`
tool in the batch forces serial regardless, and an override outranks the
tool's own declaration in both directions. A key naming a tool that does
not exist is a load-time error, not a silent no-op.

`bash` now declares itself **sequential**, which is the substantive
change: two concurrent `bash` calls touching one file used to lose an
update while both calls reported success. That bug had been sitting in
the suite as an `#[ignore]`d known defect and is now a passing test. The
cost is that a batch of two `bash` calls takes the sum of their times
rather than the max; `[tool_exec_overrides] bash = "parallel"` takes the
speed back for anyone who wants it.

### `/model` and thinking-level switches enter the transcript

`SessionEntry::ModelChange` had existed since the session format did —
serde definition, replay handling, `/export` rendering, roundtrip test —
but **nothing ever wrote one**. So switching models mid-conversation left
no trace: `--continue` replayed the whole conversation as though one
model had answered throughout, and `/export` could render a line it
would never receive data for. Both writers now exist, and
`ThinkingChange` joins it for thinking-level switches.

`thinking_change` spells "thinking off" as an **explicit `null`** rather
than an absent key, because a reader has to be able to tell "this
setting was turned off" from "this old record predates the field".

### Fixes

- **`/tools`** — the model could not reliably say what tools it had access
  to; `/tools` now lists the live registry (built-ins plus plugin-exported
  tools) via a `ToolSource`/`ToolRegistry::entries()` split.
- **Parallel tool cards keyed by `call_id`** — concurrent tool-call cards in
  the TUI no longer cross-wire their headers when multiple calls of the same
  tool run in one batch.
- **`url_allowlist` wildcard patterns** — `*` (any host, with a startup
  warning when combined with `allow_network`), `*.example.com` (subdomains
  only), and bare `example.com` (host + subdomains) are now the three
  supported spellings; a star anywhere else (`api.*.com`) is refused rather
  than silently widened.
- **Blockquote/thinking style collision** — thinking-block rendering no
  longer collides with Markdown blockquote styling in the TUI.
- **musl libunwind `bad fde` noise** — spurious unwinder warnings on musl
  builds are now suppressed outside Windows.
- **`-p` thinking/reply run-on** — non-interactive `-p` mode output no
  longer runs the thinking segment into the reply segment without a
  separator.
- **An interrupted tool call no longer bricks the session.** `tool_call`
  is written to the session file *before* the tool runs (the right order
  — for `bash`, "what is about to execute" is worth more than the
  result, because the side effect may already have happened). If the
  process died during a long call, the file ended on an orphan
  `tool_call`, which replays as an assistant `tool_use` nobody answered
  — and both APIs reject that, so the session was **permanently
  unresumable** behind a provider 400 that pointed nowhere near the
  cause. This happened most easily when you hit Ctrl-C to interrupt a
  long command. nanopi now synthesizes a result that explicitly says the
  outcome is **unknown** — not "failed", which would be a lie in the
  case that matters most, since the command very likely finished.
- **A refused prompt reads as policy, not a malfunction.** A blocked
  tool call or prompt now explains the mechanism in the result the model
  receives, and actively rules out the wrong guesses. The system prompt
  never mentioned hooks at all, so `blocked by hook: X` named something
  undefined to the model, which twice invented an environment-interceptor
  theory and burned a round chasing it.
- **Hook misconfiguration is no longer silent.** nanopi runs hooks via
  `bash -c`, so a wrong path does not fail to spawn — bash starts, finds
  nothing, and exits 127. That is neither 2 nor a JSON decision, so it
  fell into "everything else = allow" and printed *nothing*. The three
  most common mistakes all live in that branch: wrong path (127),
  **forgotten `chmod +x`** (126), and a script erroring out (1). A
  `check-rm-rf.sh` installed without the execute bit gave zero
  protection and zero notice. Calls are still allowed (turning a typo
  into a hard block on every tool call is worse than fail-open); the
  change is that the exit code is now named, with the likely cause.
- **A compaction that never ran no longer claims it did.** A short
  session fits entirely inside the 20k-token verbatim tail, so there is
  no head to summarize and not compacting is correct. The old line could
  only compare character counts, so it reported `[compacted: 2158 → 2158
  chars]` — conflating "compacted but nothing shrank" with "never
  compacted". It now reads `[nothing to compact: N chars all fit in the
  20 k-token tail kept verbatim]`, and — the other half of the same bug
  — the hooks no longer fire unpaired. `session_before_compact` used to
  fire with `session_compact` never following, which from a hook
  author's side is indistinguishable from nanopi crashing mid-compaction.
  Now neither fires.
- **The exit hint names the session you were actually in.** `/new`,
  `/resume`, `/fork` and `/import` updated the session id, but the exit
  banner was bound once at startup and never reassigned — so any run
  that switched sessions printed the *startup* session's id. Copying
  that `--session` command sent you back to a conversation you had
  abandoned, undetectably, because both ids were valid UUIDs. The
  abbreviated `✓ session <first 8> saved` line is also gone: UUIDv7
  puts the timestamp in the high bits, so same-day sessions differ only
  in the last few characters, and truncating to 8 printed something that
  looked like a whole id directly above the real one.
- **A steer that misses its turn no longer vanishes.** The steer pump
  only ran at the top of an iteration, so a turn ending in `Stop` with
  no tool call — the common case — had no next iteration to collect the
  injected message. It rotted in the channel: never in the context,
  never on disk, never seen by the model, while the TUI had already
  drawn `[steer]` to say it was accepted. The consequence was worse than
  one lost line — on resume you saw a question and an answer to a
  *different*, unrecorded question, so the next turn read a fabricated
  history.
- **`note!` lines reach scrollback instead of being wiped.** In raw
  mode `\n` moves down without returning to column 0, so the ~35
  `eprintln!` sites across the program printed in a staircase — plugin
  logs, stream-retry notices, hook diagnostics, `/model` vendor
  warnings. They also wrote inside the region ratatui manages, so the
  next redraw erased them: readable for one frame. Both are fixed at the
  single shared `note!` site — during TUI ownership it queues and the
  main loop drains via `insert_before`. The two cases without a drainer
  are handled rather than assumed: shutdown flushes the queue to stderr
  after raw mode is off, and a loop that has stopped ticking cannot grow
  the queue past `MAX_PENDING`.
- **An unknown slash command no longer bills a turn.** `/greet` is
  refused with a `Did you mean …?` suggestion (in-repo edit distance, no
  new dependency) and, non-optionally, the `//greet` escape hatch —
  refusing input without saying how to send it anyway just trades a
  wasted turn for being stuck. The refusal is narrowed to words that
  could really be a command name: no whitespace, no `/`, no `.`, so a
  pasted file path (`/etc/nginx/nginx.conf is misconfigured`) still
  reaches the model. The command palette is the single source of command
  names, plugin-registered ones included; the second hardcoded list that
  used to exist is what made a leading space send fourteen commands to
  the model, and that accident is gone.
- **A matcher that can never fire is a load-time error.** `input`
  carries no tool name, so any `matcher` other than `*` was tested
  against an empty string and silently never fired. The fix is not a
  special case for `input`: `HookEvent::matcher_subject` declares a
  matching subject for all eleven events (tool name / turn number /
  session id / compaction reason / nothing), `input` is simply today's
  only "nothing", and the arm is exhaustive so a future event is
  covered by the same rule automatically.
- **A bad matcher refuses startup instead of disarming every hook.**
  The validation above was correct and unit-tested, but both call sites
  caught the error, printed `warning: failed to load settings`, and
  substituted an empty `HooksConfig` — dropping *every* hook in the
  file, not just the offending entry. A config pairing one bad matcher
  with a working veto hook ran with the veto silently disarmed behind a
  warning that scrolls away. Now fatal, matching the severity an unknown
  hook event key has always had.
- **Shift+Tab actually cycles the thinking level.** A terminal sends
  `ESC [ Z`, which crossterm reports as `BackTab` *with* the SHIFT
  modifier; the default binding was stored as `BackTab` with no
  modifier, and the equivalence check beside it listed every spelling
  except the one that arrives. The documented default chord was
  unreachable in every real terminal — only a `[keybindings]` rebind
  reached the feature.
- **Extended thinking works on the Claude 5 family.** The
  model-capability allowlist listed 3.7 and 4.x but not 5, and the
  provider only sends the `thinking` field when that list says yes — so
  on a Claude 5 model the feature did nothing while `/thinking`, the
  status bar and the persisted `thinking_change` entry all reported it
  as on.
- **A parallel tool batch's results reach the model.** Anthropic
  requires every `tool_result` answering one assistant turn to ride in a
  single user message; nanopi emitted one message per result, and the
  API merged the consecutive user turns and then rejected the merge
  (`each tool_use must have a single result`). Every batch of two or
  more tools therefore failed *after* the tools had already run — cards
  drawn, side effects done, turn dead before the model saw anything. A
  batch of one never tripped it.
- **Long plugin names no longer run into the value beside them.**
  `/tools` padded names to 20 columns with no separator, so anything
  longer produced `nanopi-events-plugin.componentno grants`. Both
  bundled example plugins exceed that width.
- **Startup notices are grouped** into a PI-style block rather than
  scattered across stderr, and a correct dual-surface vendor config no
  longer draws a spurious warning.

## Compatibility

**Breaking: hook event names.** The four Claude-Code-named hook keys are
retired with no alias and no deprecation period:

|            old key       |          new key         |
|---------------------------|---------------------------|
| `pre_tool_use`             | `tool_execution_start`     |
| `post_tool_use`            | `tool_execution_end`       |
| `user_prompt_submit`       | `input`                    |
| `session_end`              | `session_shutdown`         |

A config using a retired key (or any misspelled hook key) fails to load;
the error names both the retired key and its replacement. `NANOPI_EVENT`
seen by hook scripts on stdin is renamed identically.

**Breaking: `session_shutdown` / `session_start` fire on more than exit.**
Both now fire around every agent swap, not just process start/exit: `/new`,
`/resume`, `/fork`, and `/import` each fire `session_shutdown` on the
outgoing agent (with `arguments.reason` set to `"new"`, `"resume"`,
`"fork"`, or `"import"`) immediately before firing `session_start` on the
incoming agent. The `matcher` field's behavior is unchanged — it still runs
against the session id.

**Breaking: honest session payloads.** `session_id` on every
session-lifecycle event (`session_start`, `session_shutdown`,
`session_before_compact`, `session_compact`) is now always the real session
id; it previously held the compaction reason (`"threshold"` / `"manual"`)
on the two compaction events. `NANOPI_SESSION_ID` is fixed the same way. The
reason for any session-lifecycle event now lives exclusively in
`arguments.reason` (values include `"startup"`, `"quit"`, `"new"`,
`"resume"`, `"fork"`, `"import"`, `"threshold"`, `"manual"`). A hook that
used to read `session_id` to distinguish a compaction's cause must now read
`arguments.reason` instead. The `matcher` field's subject for compaction
events is unchanged.

**Behaviour change: `message_end` hooks now receive the reply text.**
`arguments` gained `response` and `response_truncated`. Anything reading
`turn_count` or `response_length` is unaffected — `response_length` still
means the whole reply's byte length. But a `[[hooks.message_end]]` script
that logs `arguments` wholesale, bills by payload size, or assumes a small
fixed payload now sees up to 16 KiB of reply text per turn. Check those
before upgrading. The payload is shared byte-for-byte with WASM plugins by
contract, so this is one change in one place, not two.

**Behaviour change: an unsatisfiable `matcher` is now fatal.** An
`[[hooks.input]]` entry with any `matcher` other than `"*"` previously
loaded and silently never fired; it now refuses startup and names the fix.
If you have such an entry, change it to `matcher = "*"` and filter inside
your command. A settings error of any kind is now fatal rather than
degrading to "no hooks at all".

**Behaviour change: `bash` is sequential by default.** A batch of `bash`
calls now costs the sum of their durations rather than the max. This buys
the fix for concurrent `bash` calls losing each other's writes while both
reported success. Set `[tool_exec_overrides] bash = "parallel"` to restore
the previous behaviour.

**Behaviour change: unknown slash commands are refused.** Input that looks
like a command name (no whitespace, no `/`, no `.`) and matches no
registered command is no longer sent to the model as chat. Use `//name` to
send it as text. A leading space is no longer an escape hatch — it now
behaves identically to no leading space.

No other breaking changes. `write`/`edit` path confinement (introduced in
v0.11.0) continues to reject `../` and outward-pointing symlinks; existing
configs that stayed inside the working directory are unaffected.

## Under the hood

- `HookEvent` enum renamed at the four retired variants; `#[serde(rename_all
  = "snake_case")]` still drives the on-disk key.
- `HooksSection` (TOML deserialization struct, `src/settings.rs`) now
  carries `#[serde(deny_unknown_fields)]`, which is what turns a retired or
  misspelled hook key into a hard parse error instead of a silent no-op.
  `retired_hook_key_error` (`src/agent/hook.rs`) rewrites the raw
  `toml::de::Error` text into a message naming both the retired key and its
  replacement; wired into both `src/config.rs::load_one` and
  `src/settings.rs::load_one`.
- `run_session_hooks` (`src/agent/hook.rs`) now takes separate `subject`
  and `session_id` parameters — `subject` is what `matcher` tests against
  (session id for start/shutdown, compaction reason for the two compaction
  events), `session_id` is always the real session id, and `arguments:
  Value` on the payload carries `{"reason": ...}` for all four events.
- New `swap_agent_with_reason` seam in `src/mode/tui.rs`: fires
  `session_shutdown` on the outgoing agent, swaps, then fires
  `session_start` on the incoming agent — call sites for `/new`, `/resume`,
  `/fork`, `/import` all route through it.
- `tool_exec_mode` (`src/config.rs`): `"parallel"` (default) or
  `"sequential"`.
- WASM plugin system behind `--features wasm` (`src/wasm/`); the `Store`/
  `Config` stay synchronous, network is bridged by a worker thread +
  `mpsc`, so `ComponentBridge` is untouched.
- `src/command.rs` (plugin slash commands) is deliberately non-gated so
  `mode/tui.rs` keeps zero `cfg(feature = "wasm")`.
- ~20 hardening fixes after the v0.11.0 feature work: plugin epoch
  deadlines, trap isolation, `url_allowlist` backslash bypass, cwd-guard
  escapes in `write`/`edit`, cancel-safety of parallel tool batches,
  session-file corruption on cancel, and more.
- `Agent::reload_extensions` (`src/agent/build.rs`) returns an
  `ExtensionReloadReport` (`replaced` / `failed` / `retired` / `tools` /
  `commands` / `dropped_contributions` / `notes`), and its doc comment
  carries the per-kind state reasoning.
- Per-plugin instance ids plus a name-keyed generation table
  (`src/wasm/generation.rs`); `staleness` and `staleness_after_running`
  in `src/wasm/loader.rs` are the two refusal wordings.
- `ToolRegistry::unregister_plugin` — the missing half of
  `register_external`, needed because `register_external` refuses rather
  than overwrites.
- `Tool::execution_mode` plus `config.tool_exec_overrides`.
