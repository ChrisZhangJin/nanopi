# nanopi v0.12.0

One vocabulary for hook events, honest session payloads, and a handful of
fixes that landed on top of v0.11.0's tool-execution and WASM-extension work.

## Highlights

### One vocabulary for the eleven events

nanopi's hooks used to mix two naming schemes: four events borrowed Claude
Code's own names (`pre_tool_use`, `post_tool_use`, `user_prompt_submit`,
`session_end`), while the other seven already used PI's names
(`before_agent_start`, `turn_start`, `turn_end`, `message_end`,
`session_start`, `session_before_compact`, `session_compact`). v0.12 finishes
the migration: the four Claude-Code-named events are renamed to PI's names,
so every hook key in `[[hooks.*]]` — and every `NANOPI_EVENT` value a hook
script sees on stdin — now speaks one vocabulary.

|            old key       |          new key         |
|---------------------------|---------------------------|
| `pre_tool_use`             | `tool_execution_start`     |
| `post_tool_use`            | `tool_execution_end`       |
| `user_prompt_submit`       | `input`                    |
| `session_end`              | `session_shutdown`         |

There is no alias and no deprecation window: a config using one of the
left-hand keys fails to load, and the error names the right-hand
replacement so the fix is a one-line edit.

### Steer / follow-up injection

Mid-stream typing steers the running turn; queued follow-ups auto-start the
next one.

### WASM extensions

Behind `--features wasm` (`src/wasm/`). Components declared in
`[[extensions]]` are compiled, instantiated, and their exported tools
registered alongside the built-ins. Capabilities: `host-log`, `host-fs-read`
(read-only, cwd-confined, symlink-aware), `host-http-get` (gated on
`allow_network`, then a deny-by-default host-matching `url_allowlist`; 10s
timeout, 1 MiB body cap, redirects not followed).

### Plugin slash commands

A component may export `list-commands` / `execute-command` from a second WIT
world, `extension-commands`, and its commands appear in the `/` palette
tagged with the plugin's name. A command returns an action rather than
calling back into the host, so the import list stays at three:
`{"print"}` writes to scrollback (never seen by the model),
`{"send_user_message"}` starts or steers a turn (always echoed verbatim
first), `{"error"}` is shown only to the user. Collisions are refused, never
renamed. Plugins load once per Agent — at startup and on `/new`, `/resume`,
`/fork`, `/import`; `/reload` does not re-read this section.

### The Pi lifecycle hooks

Eleven hook events cover the full agent lifecycle: `before_agent_start`,
`turn_start`, `turn_end`, `message_end`, `tool_execution_start`,
`tool_execution_end`, `input`, `session_start`, `session_shutdown`,
`session_before_compact`, `session_compact`.

### WASM plugins can watch lifecycle events

A third, opt-in WIT world, `extension-events`, adds `list-events` /
`handle-event` so a plugin can observe (never veto or transform) the same
eleven lifecycle events shell hooks already see. Delivery requires **two
lists to agree** — the plugin's own `list-events` export AND the config's
`[[extensions]].events` grant; either alone delivers nothing. Payloads are
byte-identical to what a shell hook receives on stdin for the same event.
Guest handlers get a 2s epoch budget (vs 30s for tool calls) and delivery is
drop-on-busy rather than blocking, so a plugin mid-tool-call never stalls an
emit. `/tools` gained a "Watching events" section listing every subscribed
plugin, so the capability is never invisible.

### `tool_execution_end` can rewrite results

Not just observe them — a hook's stdout can transform the tool's result
before it reaches the model. (Named `post_tool_use` prior to this release.)

### Configurable tool exec mode

`tool_exec_mode = "parallel" | "sequential"` (`src/config.rs`). In parallel
mode, `edit` and `write` calls targeting the same file are still detected by
resolved path and serialized in emission order; `sequential` serializes the
entire batch, useful when the model drives shell-based rewrites of the same
files.

### `write`/`edit` confined to the working directory

Paths are canonicalized before any write, so `../` and outward-pointing
symlinks are refused.

### Inlined `<think>` blocks render as thinking

Some vendors served over the OpenAI-compatible wire (Xiaomi MiMo, MiniMax)
inline their reasoning as literal `<think>…</think>` tags inside the reply
text instead of a separate field. nanopi now recognizes those tags — even
when a delta splits the tag mid-stream — and renders the enclosed text as
dim-italic thinking instead of ordinary reply text. The reasoning also stops
entering the context, the session transcript, and the `-p --output json`
envelope, matching how the Anthropic-native wire already handles reasoning.
`inline_think_tags = true | false` in `config.toml` is the escape hatch: set
it to force the behavior on for an unlisted gateway, or off if a model's
answer legitimately contains a literal `<think>` tag.

### Fixes

- **`/tools`** — the model could not reliably say what tools it had access
  to; `/tools` now lists the live registry (built-ins plus plugin-exported
  tools) via a `ToolSource`/`ToolRegistry::entries()` split.
- **Parallel tool cards keyed by `call_id`** — concurrent tool-call cards in
  the TUI no longer cross-wire their headers when multiple calls of the same
  tool run in one batch.
- **`url_allowlist` wildcard patterns** — `*` (any host, with a startup
  warning when combined with `allow_network`), `*.example.com` (subdomains
  only), and bare `example.com` (host + subdomains) are now the three
  supported spellings; a star anywhere else (`api.*.com`) is refused rather
  than silently widened.
- **Blockquote/thinking style collision** — thinking-block rendering no
  longer collides with Markdown blockquote styling in the TUI.
- **musl libunwind `bad fde` noise** — spurious unwinder warnings on musl
  builds are now suppressed outside Windows.
- **`-p` thinking/reply run-on** — non-interactive `-p` mode output no
  longer runs the thinking segment into the reply segment without a
  separator.

## Compatibility

**Breaking: hook event names.** The four Claude-Code-named hook keys are
retired with no alias and no deprecation period:

|            old key       |          new key         |
|---------------------------|---------------------------|
| `pre_tool_use`             | `tool_execution_start`     |
| `post_tool_use`            | `tool_execution_end`       |
| `user_prompt_submit`       | `input`                    |
| `session_end`              | `session_shutdown`         |

A config using a retired key (or any misspelled hook key) fails to load;
the error names both the retired key and its replacement. `NANOPI_EVENT`
seen by hook scripts on stdin is renamed identically.

**Breaking: `session_shutdown` / `session_start` fire on more than exit.**
Both now fire around every agent swap, not just process start/exit: `/new`,
`/resume`, `/fork`, and `/import` each fire `session_shutdown` on the
outgoing agent (with `arguments.reason` set to `"new"`, `"resume"`,
`"fork"`, or `"import"`) immediately before firing `session_start` on the
incoming agent. The `matcher` field's behavior is unchanged — it still runs
against the session id.

**Breaking: honest session payloads.** `session_id` on every
session-lifecycle event (`session_start`, `session_shutdown`,
`session_before_compact`, `session_compact`) is now always the real session
id; it previously held the compaction reason (`"threshold"` / `"manual"`)
on the two compaction events. `NANOPI_SESSION_ID` is fixed the same way. The
reason for any session-lifecycle event now lives exclusively in
`arguments.reason` (values include `"startup"`, `"quit"`, `"new"`,
`"resume"`, `"fork"`, `"import"`, `"threshold"`, `"manual"`). A hook that
used to read `session_id` to distinguish a compaction's cause must now read
`arguments.reason` instead. The `matcher` field's subject for compaction
events is unchanged.

No other breaking changes. `write`/`edit` path confinement (introduced in
v0.11.0) continues to reject `../` and outward-pointing symlinks; existing
configs that stayed inside the working directory are unaffected.

## Under the hood

- `HookEvent` enum renamed at the four retired variants; `#[serde(rename_all
  = "snake_case")]` still drives the on-disk key.
- `HooksSection` (TOML deserialization struct, `src/settings.rs`) now
  carries `#[serde(deny_unknown_fields)]`, which is what turns a retired or
  misspelled hook key into a hard parse error instead of a silent no-op.
  `retired_hook_key_error` (`src/agent/hook.rs`) rewrites the raw
  `toml::de::Error` text into a message naming both the retired key and its
  replacement; wired into both `src/config.rs::load_one` and
  `src/settings.rs::load_one`.
- `run_session_hooks` (`src/agent/hook.rs`) now takes separate `subject`
  and `session_id` parameters — `subject` is what `matcher` tests against
  (session id for start/shutdown, compaction reason for the two compaction
  events), `session_id` is always the real session id, and `arguments:
  Value` on the payload carries `{"reason": ...}` for all four events.
- New `swap_agent_with_reason` seam in `src/mode/tui.rs`: fires
  `session_shutdown` on the outgoing agent, swaps, then fires
  `session_start` on the incoming agent — call sites for `/new`, `/resume`,
  `/fork`, `/import` all route through it.
- `tool_exec_mode` (`src/config.rs`): `"parallel"` (default) or
  `"sequential"`.
- WASM plugin system behind `--features wasm` (`src/wasm/`); the `Store`/
  `Config` stay synchronous, network is bridged by a worker thread +
  `mpsc`, so `ComponentBridge` is untouched.
- `src/command.rs` (plugin slash commands) is deliberately non-gated so
  `mode/tui.rs` keeps zero `cfg(feature = "wasm")`.
- ~20 hardening fixes after the v0.11.0 feature work: plugin epoch
  deadlines, trap isolation, `url_allowlist` backslash bypass, cwd-guard
  escapes in `write`/`edit`, cancel-safety of parallel tool batches,
  session-file corruption on cancel, and more.
