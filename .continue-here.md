## The one real design decision

**wasmtime host functions registered via `func_wrap` are synchronous.
`reqwest` is async, and nanopi's `Cargo.toml` does not enable its
`blocking` feature.** Something has to give. Three options:

1. **`reqwest` `blocking` feature.** Simplest to write, but it spawns
   its own runtime internally — calling it from inside the existing
   tokio runtime panics ("cannot start a runtime from within a
   runtime"). Would need `tokio::task::block_in_place` around it, which
   in turn requires the multi-thread scheduler (nanopi uses
   `rt-multi-thread`, so this is available). Adds compile time and
   binary size to the default build unless the feature is scoped to
   `wasm`.
2. **`func_wrap_async`** (exists on `Linker`, seen at
   `wasmtime-19.0.2/src/runtime/component/linker.rs:445`). Keeps
   everything async, but requires the `Store` to be async-configured
   (`Config::async_support(true)`), which changes how *every* existing
   call into the guest is made — `TypedFunc::call` becomes
   `call_async`. Touches `ComponentBridge`, which is currently sync
   behind a `Mutex`.
3. **Dedicated thread + channel.** Host fn sends the request to a
   worker thread owning its own single-thread runtime, blocks on a
   `std::sync::mpsc` reply. Isolates the change entirely to the new
   host function; nothing existing moves.

**My read:** option 3 is the least invasive and the easiest to reason
about, at the cost of one extra thread per plugin-with-network. Option
2 is the "correct" long-term shape but drags the whole bridge async in
a session that should stay narrow. Decide before writing code.

## What to implement

Follow the `host-fs-read` shape exactly — it is the template, and the
mechanism is already proven end to end.

### 1. `wit/nanopi-extension.wit`
Add alongside `host-fs-read`:

```wit
    /// Fetch a URL over HTTP(S) and return the response body.
    /// Gated on `allow_network = true`; the URL must additionally
    /// match `url_allowlist`.
    import host-http-get: func(url: string) -> string;
```

### 2. `src/wasm/loader.rs`
- `PluginState` already carries `url_allowlist: Vec<String>` (currently
  `#[allow(dead_code)]` — drop that attribute once it's read). Add
  `allow_network: bool` next to the existing `allow_fs`.
- New `linker.root().func_wrap("host-http-get", ...)` right after the
  `host-fs-read` one. Same in-band error convention: return
  `error: <reason>` rather than trapping.
- Gate order matters for good messages: deny when `!allow_network`
  first (naming the config knob), then check the allowlist, then
  fetch.
- Write a `url_allowed(url, allowlist)` helper next to
  `resolve_readable`. **Empty allowlist = deny everything**, matching
  what `config.toml.example` already promises. Match on host, not
  substring — `evil.com/?x=api.github.com` must not pass a naive
  `contains` check. That class of bug is exactly what the fs tests
  caught for paths.
- Set a request timeout (10s is reasonable). A plugin must not be able
  to hang a turn indefinitely.

### 3. `src/wasm/mod.rs`
`load_all` already forwards `cfg.url_allowlist`; add `cfg.allow_network`
to the `engine.load(...)` call. Signature grows by one bool.

### 4. `examples/wasm-plugin/src/lib.rs`
Add a `fetch` tool calling `host_http_get`. **Remember the ABI
asymmetry** (documented in the example's README): an *import* returning
a string takes the return area as a trailing out-param —
`fn host_http_get_raw(ptr: *const u8, len: usize, ret_area: *mut u8)`.
Copy the `host_fs_read` wrapper.

### 5. Regenerate the fixture
Commands are in the header of `tests/wasm_plugin_integration.rs`. The
`wasm-tools component wit` output must show the new import, or the host
will fail to satisfy it.

### 6. Tests — `tests/wasm_plugin_integration.rs`
Mirror the four fs tests:
- denied without `allow_network` (message names the knob)
- denied when host not in allowlist
- **empty allowlist denies everything**
- allowed host reaches a local server — spin one up in-test rather
  than hitting the network, so CI stays hermetic

### 7. Docs
`README.md`, `README_zh.md`, `config.toml.example`,
`examples/wasm-plugin/README.md` all currently say network is "not
implemented yet / reserved / inert". All four need updating; grep for
`allow_network` to find them.
