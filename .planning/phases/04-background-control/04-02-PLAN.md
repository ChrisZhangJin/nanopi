<task type="auto" tdd="true">
  <name>Task 2: finish — commit, unchanged cleanup, auto-merge or conflict</name>
  <files>src/worktree.rs</files>
  <behavior>
    - unchanged_worktree_removed_with_branch: no edits -> Outcome::Removed; path gone, branch gone
    - committed-then-reverted (net-empty tree but 1 commit ahead) counts as changed (Addendum 3)
    - merge_no_conflict: edit new file in worktree -> Outcome::Merged{branch}; main tree has file, worktree and branch removed
    - merge_conflict: same line edited in main tree (committed) and worktree -> Outcome::Conflict{branch, path}; `git status` in main shows no merge in progress (aborted), worktree and branch still exist
    - dirty main tree that blocks merge -> treated as Conflict (kept, nothing lost)
  </behavior>
  <action>Implement `pub fn finish(&Worktree, agent_id) -> WorktreeOutcome` with `pub enum WorktreeOutcome { Removed, Merged { branch }, Conflict { branch, path, detail }, Error(String) }` plus `fn report_line(&self) -> String` producing text for the report, e.g. "worktree: merged nanopi/r1/a1 into main tree" or "worktree: CONFLICT merging nanopi/r1/a1 — merge aborted, branch and worktree kept at <path>; ask the user how to proceed". Steps per D-09..D-11: if porcelain non-empty, `git add -A` + `git commit -m "nanopi agent <id>"` in the worktree; then count `git rev-list <base>..<branch> --count`; zero -> `git worktree remove --force` + `git branch -D` -> Removed; else `git -C repo_root merge --no-edit <branch>`; success -> remove worktree + branch -> Merged; failure -> `git merge --abort` (ignore its error if no merge started) -> Conflict. Never resolve conflicts (D-11).</action>
  <verify>
    <automated>cargo test --lib worktree:: -- --test-threads=1</automated>
  </verify>
  <done>All four outcome paths tested and passing; report_line text includes branch and path.</done>
