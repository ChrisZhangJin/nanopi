<objective>
Cross-process stale-write guard (ISO-03, D-13). Each nanopi process (main or child) remembers what it read; an edit/write is refused if another process changed the file since. Writes become atomic.

Purpose: two child agents sharing one working tree cannot silently clobber each other.
Output: src/tool/file_state.rs plus guarded read/edit/write.
</objective>

Design choice (Claude's discretion): the tracker is a process-global (`std::sync::OnceLock<FileStateTracker>` exposed as `file_state::global()`), NOT a new `ToolContext` field. `ToolContext { cwd }` has ~55 construction sites; a child is its own process, so a per-process global is exactly the D-13 scope and avoids touching every constructor. Tests use a fresh `FileStateTracker::new()` instance or unique temp paths so the global does not leak between tests.
