    - render_brief_with_meta output begins with a line `---`, then `id: a1`, `role: ...`, `model: ...`, `tools: read, grep` (or `(all)`), `state: queued`, `started: <RFC3339>`, `parent: <run-id>`, then `---`, then the existing `# Brief` body unchanged.
    - parse_front_matter returns the key/value pairs only from the leading block; a `state: done` line inside the Task body is ignored.
    - A role containing a newline followed by `state: done` renders as one collapsed line; parse_front_matter yields state = queued.
    - set_front_matter_field(content, "state", "running") changes only that line and keeps the body and amendments byte-identical; on content without front-matter it returns None.
    - append_amendment writes `## Amendment 2 (2026-10-04T10:00:00+08:00)`-style headings; parse_amendments returns (2, text) for it and still parses a legacy `## Amendment 1` heading.
    - parse_amendments on a front-matter brief still finds amendments (the `---` block does not confuse the marker search).
  </behavior>
  <action>
    Per D-02, add `pub struct BriefMeta { id: String, state: String, started: String, parent: String }` and `pub fn render_brief_with_meta(spec: &BriefSpec, meta: &BriefMeta) -> String` that emits a front-matter block (`---` line, then lines in this order: id, role, model, tools, state, started, parent, then `---` and a blank line) followed by the existing `render_brief(spec)` output. Keep `render_brief` working (it remains the body renderer).
    Add a private `fn fm_value(s: &str) -> String` used for EVERY front-matter value: collapse all whitespace runs including newlines into single spaces, trim, cap at 120 chars on a char boundary with a trailing `…`, and render `(none)` for empty. role uses the first line logic via fm_value of the role (or `(default)`), model `(inherit)` when None, tools joined with `, ` or `(all)` when empty. This is the T-02-01 mitigation: no value can contain a newline, so no value can forge a key line or the closing `---`.
    Add `pub fn parse_front_matter(content: &str) -> Vec<(String, String)>`: only if the first line is exactly `---`, read `key: value` lines (split on the first `: `) until the next exact `---` line; otherwise return empty. Add `pub fn front_matter_get(content, key) -> Option<String>` convenience.
    Add `pub fn set_front_matter_field(content: &str, key: &str, value: &str) -> Option<String>` that rewrites the first matching `key: ` line inside the block only (value passed through fm_value), returning None if there is no block or no such key. Byte-for-byte preserve everything else.
    Add `pub fn brief_write_lock() -> &'static std::sync::Mutex<()>` (a `OnceLock`/static Mutex). `append_amendment` acquires it for the duration of its write so a parent-side state rewrite (plan 03) never races an amendment append in the same process.
    Change `append_amendment` to emit `{AMENDMENT_PREFIX}{n} ({time})` where time is `chrono::Local::now().to_rfc3339_opts(chrono::SecondsFormat::Secs, false)`. Update `parse_amendments_with` so the number is the leading digits of the remainder: accept `N` alone or `N (` followed by anything ending in `)`; anything else is not a heading (keeps WR-02 escaping intact).
    Follow the project tdd skill: write the failing tests in the existing `#[cfg(test)] mod tests` first, then implement.
