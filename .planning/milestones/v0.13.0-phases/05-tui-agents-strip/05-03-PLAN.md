<rendering_decision>
Verified during planning: Cargo.lock pins ratatui 0.29.0. In that version `Viewport::Inline(height)` is fixed at construction; `Terminal::set_viewport_area` is private, and `Terminal::resize` recomputes the inline area with the ORIGINAL height (registry source ratatui-0.29.0/src/terminal/terminal.rs lines 212-240). Per-frame dynamic inline-viewport growth is therefore not supported by the pinned version, and upgrading ratatui is out of scope (REQUIREMENTS). Chosen lower-risk design (05-RESEARCH Pattern 2, option 2):
- DOCK_HEIGHT stays 10. The collapsed strip (header + up to 3 rows, height from agents_strip::strip_height) takes rows from the top slack region the input box would otherwise grow into. Per D-01 it is drawn between the status line and the input box: layout becomes [Min(0) overlay/slack, Length(1) status, Length(strip_h) strip, Length(2+input_h) input, Length(1), Length(1)]. The input's max content lines become MAX_INPUT_LINES minus strip_h, clamped to at least 1.
- When an overlay menu (palette, pickers, settings) is open, the overlay wins the slack and the strip collapses to its header line only (or hides if the slack is under 5 rows) so menus never shrink.
- Expanded (D-04 "~40% of screen") cannot grow the live dock in ratatui 0.29. Instead, Ctrl+G sets agents_strip_expanded = true and prints the full detail block from agents_strip::expanded_detail_lines into scrollback through the existing insert_line path (same mechanism as Ctrl+O ExpandLastTool), which the terminal's own scrollback makes unbounded and scrollable; the in-dock rows switch to showing each agent's latest activity. Ctrl+G again, or Esc when no turn/tool is running, sets expanded = false. Deviation from "~40% live pane" is recorded in SUMMARY for owner review.
- Short terminal (< 15 rows, from term.size()) keeps the strip at its header line (D-08).
</rendering_decision>
