`host-fs-read` capability shipped in `788705c`.

(b) A `url_allowed(url: &str, allowlist: &[String]) -> bool` helper placed
directly after `resolve_readable`, with a doc comment in the same register —
explain WHY host matching rather than `contains`, naming the
`evil.com/?x=api.github.com` and `api.github.com@evil.com` cases, exactly as
`resolve_readable`'s comment explains why it canonicalizes. Extraction rules:

  - require a case-insensitive `http://` or `https://` prefix; anything else
    (including no scheme) returns false. Do not add a URL-parsing dependency —
    this is a dozen lines of `str` work.
  - authority = everything after the scheme up to the first `/`, `?`, or `#`
  - if the authority contains `@`, the host is what follows the LAST `@`
  - strip a `:port` suffix; if the authority starts with `[` (IPv6 literal),
    the host is the text up to the matching `]`

    oversight; say so in the comment

    `host == entry` OR `host.ends_with(&format!(".{entry}"))`. The leading dot
    is what makes `github.com` cover `api.github.com` without covering
    `evilgithub.com` or `github.com.evil.com`. Normalize each entry the same
    way a host is normalized (lowercase, and tolerate a user who wrote
    `https://api.github.com/` in config by stripping scheme and anything from
    the first `/`).

This function is reusable by design: if the redirect policy ever changes from
"refuse" to "re-check every hop", the same helper is what a
`redirect::Policy::custom` closure would call. Do not inline its logic into the
host function.

(c) A private `fetch_url(url: String) -> Result<String, String>` free function,
also in `loader.rs`, implementing the LOCKED bridge:

  - `let (tx, rx) = std::sync::mpsc::channel();`
  - `std::thread::spawn(move || { ... tx.send(result) ... })` — inside the
    thread build `tokio::runtime::Builder::new_current_thread().enable_all().build()`
    and `rt.block_on(async { ... })`. A runtime that fails to build is sent back
    as an `Err`, never unwrapped.
  - inside the async block: `reqwest::Client::builder()`
    `.timeout(std::time::Duration::from_secs(10))`
    `.redirect(reqwest::redirect::Policy::none())`
    `.build()`, then `.get(&url).send().await`.
  - **The redirect policy is not optional and not cosmetic.** reqwest's default
    follows up to 10 hops, and `url_allowed` only ever sees the URL the guest
    handed in. An allowlisted host answering
    `302 Location: http://169.254.169.254/latest/meta-data/` would sail through
    the gate and return cloud-metadata content, with the allowlist reporting as
    enforced the whole time. That is the same bug class as the substring match,
    one layer down. Two acceptable shapes; **implement the first**:
      * `Policy::none()` — do not follow at all. Simplest thing that is
        correct, and it keeps `fetch_url` free of allowlist state.
      * `Policy::custom(...)` re-running `url_allowed` against every hop's
        `Location` and rejecting the first failure. Only take this route if
        following redirects turns out to be genuinely required; it means
        threading the allowlist into `fetch_url`, so its signature grows.
    State in the SUMMARY which one you implemented.
  - non-2xx → `Err(format!("HTTP {}", status))`. With redirects disabled a 3xx
    lands here, so make that specific message legible as a refusal rather than
    a server error, e.g. `HTTP 302 (redirects are not followed; request the
    final URL directly)`. The test greps for the status code and the word
    `redirect`, so include both.
  - `resp.text().await`, then refuse a body over `1 << 20` bytes with
    `Err("response too large (> 1 MiB)")`. Rationale for the comment: the
    example guest allocates from a 1 MiB bump arena (see
    `examples/wasm-plugin/src/lib.rs` `ARENA_SIZE`), so an unbounded body is a
    guest OOM, not just host memory.
  - the host blocks on `rx.recv()`; a `RecvError` (worker panicked) becomes
    `Err("network worker thread died")` — do not `unwrap`, a panicking fetch
    must not take down the turn.
  - one thread per call is accepted cost (CONTEXT.md); note it in the comment
    so the next reader does not think it is an oversight.

(d) The `linker.root().func_wrap("host-http-get", ...)` registration,
immediately after the `host-fs-read` one, following its shape exactly
(`store: wasmtime::StoreContextMut<'_, PluginState>`, `(url,): (String,)`,

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| guest plugin → host network | A plugin-supplied URL string crosses into the host's HTTP client. The plugin is third-party code the user installed; the URL is fully attacker-controlled if the plugin is malicious or compromised. |
| remote server → host HTTP client | Response *headers* steer the client. A `Location` header is attacker-controlled input that can redirect the request to a host the user never approved. |
| remote server → guest memory | Response bytes cross back into the guest's 1 MiB bump arena. |
| config file → capability gate | `allow_network` / `url_allowlist` are the only things standing between an installed plugin and the network. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-l4d-01 | Elevation of Privilege | `host-http-get` gate, `src/wasm/loader.rs` | mitigate | Deny on `!state.allow_network` as the FIRST check, before the allowlist and before any client construction. Test: `http_get_denied_without_allow_network`, run with a non-empty allowlist so it cannot pass for the wrong reason. |
| T-l4d-02 | Spoofing | `url_allowed` host extraction | mitigate | Match on the parsed host, never `contains`. Strip userinfo (take after the last `@`) and require a leading `.` for subdomain matches. Three explicit bypass unit tests: query-string, userinfo, suffix (`api.github.com.evil.com`). |
| T-l4d-03 | Elevation of Privilege | reqwest redirect handling → SSRF | mitigate | `redirect::Policy::none()` (or `Policy::custom` re-checking every hop's `Location` with `url_allowed`). The reqwest DEFAULT is the vulnerability: it follows 10 hops while `url_allowed` only ever inspects the guest-supplied URL, so an allowlisted host answering `302 Location: http://169.254.169.254/latest/meta-data/` reaches cloud metadata with the allowlist reporting as enforced. Pinned by `http_get_refuses_redirect_off_the_allowlist`, which asserts the in-band refusal AND a zero hit count on the redirect target. |
| T-l4d-04 | Denial of Service | request lifetime | mitigate | 10s `Client::builder().timeout(...)`. A plugin must not be able to hang a turn on a black-holed connection. |
| T-l4d-05 | Denial of Service | guest linear memory | mitigate | Refuse bodies > 1 MiB. The example guest's arena is exactly 1 MiB (`ARENA_SIZE`), so an unbounded body is a guest allocation failure, i.e. a trap, not merely wasted host memory. |
| T-l4d-06 | Denial of Service | worker thread | mitigate | `rx.recv()` errors (panicked worker) and runtime-build failures return `Err`, never `unwrap`. One thread per call is the accepted cost of the locked design. |
| T-l4d-07 | Information Disclosure | direct SSRF to loopback / RFC1918 / metadata (`169.254.169.254`) when the user allowlists it | accept | The allowlist is the control, and it is deny-by-default with empty = deny-all. Reaching a link-local or loopback address requires the user to have written that host into `url_allowlist` themselves. Blanket private-range blocking is explicitly NOT added: it would break the hermetic tests, which deliberately allowlist `127.0.0.1`. A `url_allowed` unit test asserts this is intentional so a later "hardening" pass cannot quietly change it. Note the distinction from T-l4d-03: there, the user never approved the host at all. |
| T-l4d-08 | Information Disclosure | network egress in CI | mitigate | Tests spin up local `TcpListener`s; no test resolves or contacts an external host. Task 3's second verify command re-runs them with `http_proxy`/`https_proxy`/`all_proxy` unset to prove it. |
| T-l4d-SC | Tampering | npm/pip/cargo installs | n/a | No dependency changes. `Cargo.toml` is untouched (Task 1 verify asserts `git diff --quiet Cargo.toml`) and no new crate, feature flag, or dev-dependency is introduced — the test servers are `std::net`. No package legitimacy gate applies. |
