# Phase quick Plan 260819-ayr: First-Run Wizard Summary

Added a first-run wizard so nanopi bootstraps itself when a user runs
it with no config, no env vars, and no CLI credentials. The same
wizard is reachable explicitly via `nanopi init`.

## What Shipped

### `src/wizard.rs` (new, ~340 LOC + tests)

- `PROVIDER_PRESETS: &[ProviderPreset]` — six canonical entries in
  the spec-mandated order: OpenAI, DeepSeek, Anthropic direct, Gemini
  via gateway, Ollama, Custom.
- `is_localhost(&str) -> bool` — substring match on `localhost` /
  `127.0.0.1` / `0.0.0.0`, used to skip the api-key prompt for
  local backends.
- `probe_config(base_url, api_kind, model, api_key) -> Result<(),String>`
  — sends ONE tiny non-streaming request (`max_tokens=1`, single
  "hi" user message) via a hand-rolled `reqwest::Client::new().post`.
  Speaks either `/chat/completions` (openai) or `/v1/messages`
  (anthropic). Returns Ok on any 2xx; Err with status + 240-char
  body snippet otherwise.
- `write_key_file(path, key)` — chmod 0600 on Unix via
  `OpenOptionsExt::mode`, plain write on non-Unix. Creates parent
  dirs.
- `write_config_toml(path, model, base_url, api_kind, api_key_file)`
  — emits a minimal 4-key TOML doc with a `# generated by nanopi init`
  header. `api_key_file` is `Some("~/.nanopi/api_key")` for normal
  providers, `None` for localhost.
- `run_wizard(force_overwrite_prompt: bool)` — the async entry point:
  1. Resolves `nanopi_home()`.
  2. Optional overwrite guard when called from `init`.
  3. Numbered provider pick-list, re-prompts on invalid input.
  4. Model prompt with preset default as bracketed hint.
  5. API-key prompt (skipped for localhost).
  6. Probe → on failure, offer retry/edit/abort.
  7. On success, write key file (skipped for localhost) then config.toml.

### `src/lib.rs`

- Added `pub mod wizard;` next to `pub mod trust;`.

### `src/main.rs`

- New `is_init_subcommand(&Args) -> bool` helper — narrow match on
  `positional_message == "init"` with no other CLI-turn options set,
  so `-m init` (user actually wants to say "init") still routes to
  chat.
- Early `init` dispatch runs BEFORE `load_config` so a broken
  config.toml doesn't block reconfiguration.
- No-config fallthrough after `load_config`: when
  `args.model / OPENAI_MODEL env / cfg.model` AND
  `args.api_key / OPENAI_API_KEY env / cfg.api_key / cfg.api_key_file`
  AND `args.base_url / OPENAI_BASE_URL env / cfg.base_url` are ALL
  unresolved, prints `"nanopi: no config found — launching first-run
  wizard (Ctrl-C to abort)"`, runs the wizard, then reloads config
  and continues the resolution ladder so the user's original
  invocation proceeds.

### Tests

Six new unit tests in `src/wizard.rs::tests`:

- `presets_has_six_entries_with_custom_last`
- `preset_order_matches_spec`
- `is_localhost_recognizes_local_forms`

- `write_config_toml_round_trips_through_loader`

All six pass. `cargo check --lib` clean.
