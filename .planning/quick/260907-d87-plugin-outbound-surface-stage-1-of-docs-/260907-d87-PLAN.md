  <files>src/wasm/store.rs, src/wasm/mod.rs</files>
  <behavior>
    Seam: `PluginStore`'s public methods. Tests take a temp root, never
    the real `~/.nanopi`. Expected strings are the spec's literals, not
    recomputed.

    - `get` on a key never set returns `Ok(String::new())` — "" is the
      absent marker, and the spec's rationale is that "" is not valid
      JSON so a plugin storing JSON has no ambiguity.
    - `set` then `get` returns the value; a second `set` on the same key
      REPLACES it; `get` on a key another plugin (different root) set
      returns "" — one plugin cannot read another's keys.
    - `set` returning `Ok(())` means the bytes are on disk: after `set`,
      reading `store.json` from the filesystem with `std::fs` shows the
      value, with NO further flush call. (Invariant 8. This is the test
      that forbids an in-memory write-behind cache.)
    - a value pushing the file past 1 MiB total is refused with exactly
      `store quota exceeded (1 MiB)` AND stores nothing — assert the
      pre-existing keys are unchanged and the new key still reads "".
    - key number 1001 is refused and stores nothing; a 129-char key is
      refused and stores nothing; a 128-char key is accepted (the cap is
      inclusive — `key ≤ 128`).
    - a `store.json` that is absent, empty, or malformed JSON reads as
      an empty store rather than an error, and a following `set`
      succeeds — a torn/hand-edited file must not brick the plugin.
    - the commit is temp-file + rename: after a `set`, no leftover temp
      file remains in the directory, and the directory contains exactly
      `store.json`.
  </behavior>
  <action>
Create `src/wasm/store.rs` and declare `pub mod store;` in
`src/wasm/mod.rs` (the module lives under the `wasm` feature already, so
no extra cfg is needed).

`PluginStore` owns the mapping from a plugin-supplied KEY to a
filesystem location; the plugin never names a path. That is the whole
reason `resolve_readable`'s defense (`../`, symlinks, FIFOs, char
devices) has no analogue here — say so in the module doc, because the
next reader will otherwise ask why the containment check is missing.

Shape:
- `PluginStore::new(root: PathBuf, stem: &str)` → the store rooted at
  `root/<stem>/store.json`. Production callers pass
  `~/.nanopi/extensions` (expand `HOME` with the same convention as
  `crate::wasm::expand_path`); tests pass a temp dir. Do NOT hardcode
  the home path inside the type — that is what makes the seam testable.
- `get(&self, key: &str) -> String` — absent/unreadable/malformed → "".
- `set(&self, key: &str, value: &str) -> Result<(), String>` — the
  `Err` payload is the message body WITHOUT the `error: ` prefix; the
  caller in `loader.rs` adds the prefix, matching how
  `resolve_readable` returns bare messages.

Bounds, checked BEFORE any write, and refusing means writing nothing:
`MAX_KEY_CHARS = 128`, `MAX_KEYS = 1000`, `MAX_STORE_BYTES = 1 MiB`
measured on the serialized JSON object that WOULD be written (so a
replacement that shrinks the file is not refused for the old size).
Quota message exactly: `store quota exceeded (1 MiB)`. Key messages name
which cap was hit and its number, so a plugin author can act.

Concurrency + durability: read-modify-write the whole JSON object per
`set`, then commit by writing `store.json.tmp.<pid>-<uuid>` in the same
directory and `std::fs::rename` over `store.json` (same-directory rename
is atomic; a crash therefore leaves either the old file or the new one,
never a torn one — `plugin-capabilities.md` §4). No `fsync`: the spec is
explicit that this survives a crash, not a power cut — put that
limitation in the doc comment rather than implying more durability than
is delivered (`claims-and-races.md` §1). Use `crate::util::uuid::v7()`
for the temp suffix if that helper is in scope, otherwise pid + a
counter.

Wrap the store in `Arc<PluginStore>` so `PluginState` and
`PluginRebuild` can both hold it — the store MUST survive
`ComponentBridge::reset`, since a trap rebuilds the instance and
anything in guest memory is gone (invariant 14).

TDD: one behavior from `<behavior>` at a time, red before green. For the
"returning Ok means it is on disk" test, first confirm it FAILS against
a deliberate write-behind variant (keep the value in a `Mutex<Map>` and
flush on drop) before implementing the real commit — a test that cannot
distinguish those two is not testing invariant 8.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| guest → host import | fully attacker-controlled strings (key, value, notify text) cross into host code |
| host → filesystem | plugin-influenced writes land under `~/.nanopi/extensions/<stem>/` |
| host → terminal | plugin-authored text is rendered into the user's scrollback |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-d87-01 | Tampering | `host-store-set` key | mitigate | The key is a JSON map key, never a path component; the only filesystem name derived from plugin input is the `.wasm` stem, which comes from the user's own config, not the guest. Task 1 asserts a `../`-shaped key is stored as an ordinary key and creates no file outside the store dir. |
| T-d87-02 | Denial of Service | store quotas | mitigate | 1 MiB / 1000 keys / 128-char key checked before any write; refusal is in-band and stores nothing (Task 1). |
| T-d87-03 | Denial of Service | `host-notify` flooding | mitigate | `MAX_NOTIFY_PER_TURN` plus a 64 KiB payload cap; overflow announces its own count (Task 3). |
| T-d87-04 | Spoofing | `host-notify` attribution | mitigate | Prefix applied host-side from the file stem; payload is never parsed for attribution (Task 3). |
| T-d87-05 | Information Disclosure | cross-plugin store reads | mitigate | One directory per stem; a stem collision with `allow_store` is a load error, not a shared store (Tasks 1-2). |
| T-d87-06 | Elevation of Privilege | `allow_store` + `allow_network` | accept + warn | Both are explicit user grants; the combination gets the escalated `[Extensions]` warning (Task 2). |
| T-d87-07 | Repudiation | a `""` return that did not deliver | mitigate | `set` returns `""` only after the rename commits; `notify` returns an `error: ` string when truncated or suppressed (invariants 8-9). |
| T-d87-SC | Tampering | npm/pip/cargo installs | n/a | No new dependencies. If any task finds it needs one, stop and add the legitimacy gate before installing. |
