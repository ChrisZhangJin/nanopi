<objective>
Models served over the OpenAI-compatible wire (mimo/xiaomi, minimax) inline
their reasoning as `<think>…</think>` inside `delta.content`. nanopi prints
that as ordinary reply text, and — worse — accumulates it into
`assistant_text`, so it enters the context and the session transcript and is
re-sent every turn.

Purpose: make the two wire protocols produce the SAME transcript for the same
model. The Anthropic adapter already emits `AgentEvent::ThinkingDelta` for
reasoning; this makes the OpenAI adapter do the same for inlined tags.

Output: a tested splitter, adapter wiring behind a vendor gate with a config
escape hatch, e2e coverage, and docs.
</objective>

<design_decisions>

**D1 — The split happens in the provider adapter (`openai.rs`), not in the
renderers.**

Verified in the codebase, not assumed:
- `src/agent/loop_.rs:884` accumulates ONLY `AgentEvent::TextDelta` into
  `assistant_text` (`grep -n "ThinkingDelta" src/agent/loop_.rs` → no hits).
  `assistant_text` is what becomes `push_assistant_text` (context), the session
  record (`loop_.rs:1056-1063`), and the `--output json` envelope.
- Therefore emitting `ThinkingDelta` from the adapter fixes ALL FOUR reported
  consequences at once, and does so by matching the Anthropic-native path
  (`src/provider/anthropic.rs:590`) byte for byte.
- Splitting in the renderers (`render/stdout.rs:166`, `mode/tui.rs:3463`)
  would need the same parser twice and would leave context and session
  polluted — i.e. it would fix consequence 1 and none of 2, 3. Rejected.

**D2 — Opt-in per vendor, via a new `Vendor` trait method.**

`OpenAiProvider` already carries `pub vendor: Option<Box<dyn Vendor>>`
(`openai.rs:201`), so the gate costs nothing structurally.

`Vendor::inlines_think_tags(&self) -> bool` defaults to `false`. Overridden to
`true` for `XiaomiVendor` and `MinimaxVendor` — the two vendors observed doing
it. Every other vendor, including `FallbackVendor` and an absent vendor
(`vendor: None`), is unchanged.

Config escape hatch: `inline_think_tags: Option<bool>` on `Config`. `Some(true)`
forces the splitter on (an unlisted gateway proxying mimo), `Some(false)` forces
it off, `None` defers to the vendor. Threaded to the provider as a plain `bool`
field on `OpenAiProvider` so the adapter never re-consults config mid-stream.

**Failure mode, stated explicitly:** with the splitter ON, a mimo/minimax model
that legitimately writes a literal `<think>` tag in its ANSWER (e.g. helping the
user author a prompt) will have that span rendered dim-italic and dropped from
the transcript. That is a real, if narrow, loss. It is bounded by: (a) only two
vendors, (b) `inline_think_tags = false` turns it off, and (c) fenced code is
not special-cased — a `<think>` inside a code block WILL be eaten. This is the
accepted cost; a fence-aware parser is out of scope and would itself be a source
of silent loss. Text loss from a PARSER BUG is not accepted and is what the unit
tests exist to prevent.

**D3 — Unclosed tag recovery: flush as thinking, never swallow.**

At end of stream the splitter is drained. Whatever is buffered is emitted, not
dropped. A stream ending mid-`<think>` yields its partial reasoning as
`ThinkingDelta`; a stream ending on a partial tag prefix (`abc<thi`) emits the
prefix as `TextDelta` so no byte is lost. Invariant, asserted by test:
**concatenating every emitted Text + Think segment reproduces the input
exactly, minus only complete `<think>` / `</think>` delimiters.**

**D4 — A bare `</think>` with no opener is literal text.** Closing a state we
were never in is a model artefact, not a delimiter. Passing it through is the
non-destructive choice.

</design_decisions>

      documented behaviour, and assert the no-loss invariant still holds for the
      NON-delimiter bytes.

      `Text("")` or `Think("")` segment.

  <action>
    Create `src/provider/think_tags.rs` and register it in
    `src/provider/mod.rs` as `pub mod think_tags;`.

    Implement `Segment`, `InlineThinkSplitter`, `new`, `push`, `finish` per the
    contract in `<interfaces>`.

    Implementation shape (prose, not code): keep a `String` carry buffer and an
    `inside: bool`. On `push`, append the chunk to the carry, then loop
    scanning for the delimiter appropriate to the current state (`<think>` when
    outside, `</think>` when inside). On a hit, emit the preceding span as
    `Text` or `Think` respectively, drop the delimiter, flip `inside`, continue.
    When no full delimiter remains, compute the longest suffix of the carry that
    is a proper prefix of either delimiter, retain exactly that suffix, and emit
    the rest. The suffix search is what makes split tags work; bound it by the
    longer delimiter's length so the carry can never grow unboundedly.

    `finish` emits the entire remaining carry as one segment — `Think` if
    `inside`, `Text` otherwise — then resets state. Never discard.

    Operate on `char` boundaries throughout (`str` slicing on a byte index
    inside a multi-byte char panics, and CJK reasoning traces are the exact case
    that motivated this plan). Do not use byte indices derived from anything
    other than `find`/`char_indices`.

    No `unsafe`. No regex crate. No new dependency.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| provider SSE → adapter | Model-controlled bytes cross into nanopi's parser |
| adapter → context/session | What the splitter classifies decides what is persisted and re-sent |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-L1S-01 | Denial of Service | `InlineThinkSplitter` carry buffer | mitigate | Retained suffix is bounded by `"</think>".len()`; carry can never grow with stream length. Asserted by the byte-at-a-time test. |
| T-L1S-02 | Information disclosure | reasoning → session transcript | mitigate | D1 routes Think segments to `ThinkingDelta`, which `loop_.rs` does not accumulate; e2e `inline_think_excluded_from_json_envelope` proves it. |
| T-L1S-03 | Tampering | model emits `<think>` to hide answer text from the transcript | accept | Bounded to two vendors, disableable via `inline_think_tags = false`; the text is still shown to the user (dim-italic), only demoted. |
| T-L1S-04 | Tampering | UTF-8 boundary panic from adversarial multi-byte input | mitigate | Char-boundary-only slicing (Task 1 action); CJK covered in the split-at-every-offset loop. |
| T-L1S-SC | Tampering | dependency installs | mitigate | No new dependency is added by this plan. If one is proposed, stop and run the package legitimacy gate. |
</threat_model>
