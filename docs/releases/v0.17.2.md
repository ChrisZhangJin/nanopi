## Highlights

- **Named agents:** Each agent gets a name chosen by the dispatching model: a historical figure whose work suits the task, such as Curie for investigating or Turing for writing code. If the model gives none, nanopi picks a fallback that no other agent in the session has. The name appears next to the agent's id in the agents strip, `/agents`, agent cards, `list_agents` and report previews, and `/agents show curie` finds the agent by name. Ids are unchanged, so tools and reports keep working.
- **Clearer agents strip:** The header now reads `● agents  N working · ⊙ next check 30s · ctrl+g details`. The shared status-check countdown moved there from the footer.
- **Inline images:** nanopi detects terminals that draw iTerm2 inline images on its own: iTerm2, WezTerm, mintty and NexusTerm. Local shells are recognized from their environment; elsewhere, including over SSH, nanopi asks the terminal its name once at startup (XTVERSION), waiting at most 150 ms (500 ms over SSH). `NANOPI_INLINE_IMAGES=iterm2|off` still overrides. Images stay off under tmux unless forced. Where images work, the nanopi logo greets you above the startup banner. `/image-test` draws the logo, and `/image <path>` previews a local PNG, JPEG or GIF without sending it to the model.
- **Input history:** While you browse history with ↑/↓, the input box's top border shows the position, e.g. `History 98/100`. The history file keeps the newest 100 entries and drops the oldest as new ones arrive, so it no longer grows past that.
- **Multi-line input:** ↑/↓ move the cursor between the lines of multi-line input. History takes over only from the start of the first line (↑) or the last line (↓), and a recalled multi-line entry can be walked line by line.
- **Fix:** the input box and footer no longer disappear after the last agent finishes.
