# 0.9.3 — `/settings` menu, vendor dispatch, keybindings — design

Date: 2026-08-13
Target release: nanopi 0.9.3

## Goal

Give nanopi three things that PI has and nanopi lacks:

1. A `/settings` slash command that opens an inline picker for the
   interaction settings a user actually changes at runtime (thinking
   level, hide thinking, auto-compact, default project trust,
   keybindings).
2. A **vendor dispatch layer** — one `trait Vendor` with per-provider
   overrides (Anthropic, OpenAI, DeepSeek, Z.ai, Qwen, Minimax, Xiaomi,
   fallback) so the vendor-specific wire fiddling (thinking format,
   base URL default, stream event mapping) lives in one file per vendor
   instead of scattered branches inside the two provider adapters.
3. **User-rebindable keybindings** — currently every keybinding is a
   `match` arm on `KeyEvent` inside `interpret_key`. Replace with a
   `KeyBindings` lookup that the `/settings > keybindings` submenu
   writes to.

Out of scope: project-level `settings.toml`, the 25 other PI settings
items (transport, http-idle-timeout, steering-mode, theme picker,
editor/output padding, ui-mode, cache-miss-notices, warnings submenu,
etc.), Bedrock/Vertex/Copilot/Radius/OpenRouter vendors,
reasoning-token accounting, model-swap vendor re-inference UI notice.

## 1 · Architecture

### 1.1 New modules

- **`src/settings_toml.rs`** — loader/saver for a **new** global
  `~/.nanopi/settings.toml` schema that carries interaction settings.
  Kept separate from `config.toml`:
  - `config.toml` = deployment face (api key, base url, hooks).
  - `settings.toml` = interaction face (thinking level, hide thinking,
    auto-compact, default project trust, keybindings).

  *Naming collision note:* `src/settings.rs` already exists as the
  legacy hooks loader (`~/.nanopi/settings.toml` [[hooks.*]] fallback,
  see `src/settings.rs:1-12`). We keep that file as-is under the name
  `settings.rs`, and put the new schema in `settings_toml.rs`. The new
  loader reads the same `~/.nanopi/settings.toml` file — its
  `SettingsFile` struct only names the four interaction sections and
  `keybindings`, so serde's default-tolerant `#[serde(default)]` means
  the legacy `[hooks]` block coexists in the same TOML document
  without either loader tripping on the other's keys.

- **`src/vendor/mod.rs`** — `trait Vendor` + `pick_vendor()`
  dispatcher, plus one file per vendor:
  - `anthropic.rs`, `openai.rs`, `deepseek.rs`, `zai.rs`, `qwen.rs`,
    `minimax.rs`, `xiaomi.rs`, `fallback.rs`
  - Shared behaviour goes in `trait Vendor` default methods; each
    vendor file overrides only what differs. This is Rust's idiomatic
    version of "base class + override" — chosen over generic
    composition because the delta between vendors is small enough
    that trait defaults win on readability.

- **`src/keys.rs`** — `enum ActionId`, `struct KeySpec`,
  `struct KeyBindings`. See §2.3.

### 1.2 Refactors

- **`src/mode/tui.rs`**:
  - Gains a `/settings` slash command entry in the palette dispatch.
  - Gains a `SettingsMenu` component (structure mirrors the existing
    `MenuState<T>` picker used for model/fork/resume).
  - The hardcoded `KeyCode::BackTab` match at `src/mode/tui.rs:858-864`
    (and every peer hardcoded match in `interpret_key`) becomes
    `bindings.matches(ActionId::ThinkingCycle, k)`.
  - Footer at `src/mode/tui.rs:3485-3495` gets a `· vendor:<id>`
    segment when `pick_vendor()` returned a non-fallback vendor.

- **`src/provider/mod.rs::build()`** — calls
  `pick_vendor(cfg.provider, base_url, model)` and passes the
  returned `Box<dyn Vendor>` to whichever transport
  (`OpenAiProvider`/`AnthropicProvider`) the vendor's `transport()`
  method points to. `ApiKind` stays but is demoted to a **fallback
  override**: if the vendor detection returns `Fallback` and
  `config.api_kind` is set, honor `api_kind`. If a specific vendor
  was detected, its `transport()` wins over `api_kind`.

- **`src/config.rs`** — add optional `provider: Option<String>`.
  Everything else in `Config` stays untouched.

## 2 · Data model

### 2.1 `SettingsFile`

```rust
#[derive(Debug, Clone, Default, Deserialize, Serialize)]
#[serde(default)]
pub struct SettingsFile {
    pub thinking_level:         Option<ThinkingLevel>,   // off/minimal/low/medium/high/xhigh/max
    pub hide_thinking:          Option<bool>,
    pub auto_compact:           Option<bool>,
    pub default_project_trust:  Option<TrustLevel>,      // reuse existing enum
    pub keybindings:            HashMap<ActionId, KeySpec>, // sparse
}
```

All fields `Option` / default-empty so a partial file loads cleanly and
so `settings.toml` can be written incrementally as the user changes
one setting at a time.

Persistence uses **`toml_edit = "0.22"`** (new Cargo dep) rather than
`toml`. Reason: `toml_edit` preserves user comments and key ordering
on rewrite. `toml`'s Serialize output reshuffles everything.

### 2.2 `ActionId`

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub enum ActionId {
    ThinkingCycle,        // currently Shift+Tab
    ToolCancel,           // currently Esc during streaming
    ExpandLastTool,       // currently Ctrl+O or similar (see interpret_key)
    NewlineInInput,       // currently Ctrl+J
    OpenSlashPalette,     // currently first '/' at BOL
    OpenSettings,         // new; default: none — invoked only via /settings
    // room to grow — add via patch, do not preemptively bloat
}
```

**Explicitly not covered** by `ActionId` (kept hardcoded):

- **`Esc Esc` → fork picker**. This is a key *sequence*, not a chord;
  see §3.2 for why sequence bindings are not exposed in the editor.
- **`/` at column 0** to open the palette is technically an
  `OpenSlashPalette` action, but the trigger is a *character in the
  input buffer*, not a keybinding. It stays as `text_buffer`
  processing.
- Ctrl+C / Ctrl+D exit paths — untouched, no user demand to rebind.

### 2.3 `KeySpec`

```rust
#[derive(Debug, Clone, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub struct KeySpec {
    pub code: KeyCode,    // wraps crossterm::event::KeyCode
    pub mods: KeyModifiers,
    // `follow` was considered for sequence bindings (Esc Esc, etc.);
    // §3.2 removed sequences from scope. If the impl finds it doesn't
    // need the field to satisfy any test, DROP it — a single-chord
    // struct is simpler. If any code path still wants sequences
    // internally, keep it as `Option<Box<KeySpec>>`.
    // pub follow: Option<Box<KeySpec>>,
}
```

Serialization uses the human string form: `"ctrl+shift+t"`,
`"shift+tab"`, `"esc"`. `KeySpec::parse(&str) -> Result<Self, _>` +
`Display` for round-tripping. Case-insensitive on parse.

`KeyBindings` is a wrapper around `HashMap<ActionId, KeySpec>` with:

- `default() -> Self` — hardcoded defaults matching today's behaviour.
- `from_file(map) -> Self` — start from defaults, then overlay user
  entries. Missing keys stay at default.
- `matches(action, KeyEvent) -> bool` — the runtime check.
- `set(action, spec) -> Option<ActionId>` — installs the binding;
  returns `Some(prev_owner)` if `spec` was previously bound to
  another action (used by the conflict prompt in §3.3).
- `save(path)` — writes only entries that DIFFER from default, via
  `toml_edit`.

### 2.4 `trait Vendor`

```rust
pub trait Vendor: Send + Sync {
    fn id(&self) -> &'static str;

    /// Which wire transport carries this vendor's requests.
    fn transport(&self) -> ApiKind;

    /// Default base_url when config.toml omits it. Callers use this
    /// only if config.base_url is unset AND the environment doesn't
    /// override.
    fn default_base_url(&self) -> Option<&'static str> { None }

    /// Whether extended-thinking makes sense for this (vendor, model).
    /// Default: false. Anthropic/DeepSeek/Z.ai/Minimax override.
    fn supports_thinking(&self, model: &str) -> bool { false }

    /// Vendor-specific request-body tweaks (headers/body fields).
    /// Called from provider `build_request` after the transport builds
    /// its base body. Default: no-op.
    fn adapt_request(&self, body: &mut Value, ctx: &BuildCtx, model: &str) {}

    /// Emit the thinking parameters into `body`. Called ONLY when
    /// ctx.thinking is Some AND self.supports_thinking(model). Default
    /// emits OpenAI-style `reasoning_effort`; Anthropic overrides.
    fn write_thinking(&self, body: &mut Value, level: ThinkingLevel, model: &str) {
        body["reasoning_effort"] = json!(level.openai_effort_string());
    }

    /// Map a raw SSE JSON event to an AgentEvent. Default matches the
    /// current OpenAI SSE shape; Anthropic overrides.
    fn map_stream_event(&self, ev: &Value) -> Option<AgentEvent> { openai_default(ev) }
}
```

### 2.6 `pick_vendor(cfg_provider, base_url, model) -> Box<dyn Vendor>`

Priority order:

1. **Explicit** `config.provider` string. If `Some("deepseek")` etc.,
   return that vendor. Unknown string → warn + fall through.
2. **Base-URL domain sniff**:
   - `api.deepseek.com`             → DeepSeek
   - `api.z.ai`                     → Z.ai
   - `dashscope.` or contains `qwen` → Qwen
   - `minimax` in the host          → Minimax
   - `xiaomimimo`                   → Xiaomi
   - `anthropic.com`                → Anthropic
3. **Model prefix** — only when base_url is unset or generic:
   - starts with `claude-`          → Anthropic
   - starts with `gpt-`, `o1`, `o3`, `chatgpt-` → OpenAI
   - starts with `deepseek-`        → DeepSeek
   - starts with `glm-`             → Z.ai
   - starts with `qwen-`, `qwq-`    → Qwen
   - starts with `MiniMax-`         → Minimax
4. **Fallback** — `FallbackVendor` (== OpenAI shape, no
   `default_base_url`, no thinking).

`ApiKind` (the pre-0.9.3 selector) becomes the tiebreak only when
`pick_vendor` returns `Fallback` — otherwise the vendor's `transport()`
wins. Existing `--api-kind` CLI flag preserved unchanged.

## 3 · TUI flow

### 3.1 `/settings` menu

Opens a `SettingsMenu` component (inline picker, same widget family as
model_picker / fork_picker). Five rows:

```
Thinking level          medium  ▸
Hide thinking output    off     ▸
Auto-compact            on      ▸
Default project trust   ask     ▸
Keybindings             ▸
```

- Enter or Space on rows 1–4 cycles the enum value. Change is
  immediately persisted (`SettingsFile::save`) and applied to the
  running `App` — no OK/Apply button.
- Row 5 opens the keybindings submenu (§3.3).
- Esc closes.

### 3.2 Sequence bindings intentionally out of scope

Only single-chord bindings are user-editable. `Esc Esc` for the fork
picker, and any other sequence, stays hardcoded in `interpret_key`.

Reason (recorded per brainstorm): the editor UX for a two-step
"press A, then press B" capture is a rabbit hole with poor
cost/benefit ratio for 0.9.3. If demand appears later, we add a
`follow: Option<Box<KeySpec>>` field to `KeySpec` (which the
scaffolding already anticipates in §2.3) and a two-step capture
modal.

### 3.3 Keybindings submenu

- Lists each `ActionId` and its current binding (as `KeySpec::display`).
- Enter on a row opens a **capture modal** — `App` enters a
  `capture_key_for: ActionId` state; the next `KeyEvent` becomes the
  new binding (except Esc, which cancels).
- **Conflict resolution**: if the captured `KeySpec` was already
  bound to a different action, show `"conflicts with <other>, overwrite? y/n"`.
  On `y`, install the new binding and *unbind* the loser (the loser's
  row shows `(unbound)` afterwards). On `n`, cancel — no change.
- **No lock list.** Every listed `ActionId` is rebindable. If the user
  binds `ThinkingCycle` to `Enter`, they've broken their input; that's
  their call. (User explicitly waived a lock list.)

### 3.4 `interpret_key` uses `bindings.matches`

Every hardcoded chord match in `interpret_key` becomes
`if app.bindings.matches(ActionId::X, k) { ... }`. Sequence handling
(`Esc Esc`) stays as-is — it's not in `ActionId`.

### 3.5 Footer

The line 2 footer already renders
`<cwd> · branch · model · think:<level> · <ctx%>`
(see `src/mode/tui.rs:3485-3495`). We add one more segment **only when
`pick_vendor` returned a non-Fallback vendor**:

```
… · model · think:high · vendor:deepseek · 1.4%/128k (auto)
```

Position: right after the `think:` segment. Style: same
`Color::Indexed(108)` italic as `think:` for visual grouping.

### 3.6 Startup error handling

- `SettingsFile::load()` I/O failure → red one-line stderr warning
  (`nanopi: settings.toml unreadable: <err>; using defaults`); do
  NOT crash.
- Malformed TOML → same, but include the parse error line.
- One bad key string in `[keybindings]` → warn about *that* action
  only; fall back to its default; other bindings unaffected.
- Unknown `ActionId` (future-added) → silently ignored on load, and
  preserved by `toml_edit` on save (comment stays). No error.

## 4 · Test strategy

Reuse the existing pattern from `src/session.rs` tests:
`crate::TEST_LOCK` (global mutex) + `NANOPI_HOME` env redirection for
FS isolation. Cleanup in each test body via `std::fs::remove_dir_all`.

### 4.1 Per-module unit tests

- **`agent::thinking`** — add serde `Serialize`/`Deserialize` +
  round-trip test. Every `ThinkingLevel` variant serialises to
  lowercase name (`"off"`, `"minimal"`, …, `"max"`).

- **`keys`**:
  - `KeySpec::parse("ctrl+shift+t")` round-trips through `Display`.
  - `KeySpec::parse("shift+tab")` yields `KeyCode::Tab` + SHIFT
    (equivalent to BackTab — must map correctly).
  - `KeyBindings::default().matches(ActionId::ThinkingCycle,
    KeyEvent { code: BackTab, mods: NONE })` returns true.
  - `set()` returns `Some(prev)` on collision.
  - `save()` emits only diff entries.

- **`settings_toml`**:
  - Round-trip preserves user comments (write, mutate one key,
    write again, assert comment survived — this is the `toml_edit`
    guarantee test).
  - Missing file → `SettingsFile::default()`.
  - Malformed file → warn on stderr + defaults (assert on captured
    stderr).

- **`vendor`** — one test per vendor's `write_thinking` output.
  Sample body starts as `json!({})`; call `write_thinking(body,
  ThinkingLevel::High, model)`; assert the exact JSON in §2.5 above.

  Additional:
  - `pick_vendor(Some("deepseek"), _, _)` returns DeepSeek.
  - `pick_vendor(None, Some("https://api.z.ai/api/paas/v4"), _)`
    returns Z.ai.
  - `pick_vendor(None, None, "claude-opus-4-7")` returns Anthropic.
  - `pick_vendor(None, None, "gpt-4o")` returns OpenAI.
  - `pick_vendor(None, None, "MiniMax-M2")` returns Minimax with
    `transport() == Anthropic`.

- **`provider::mod`** — replaces two current tests:
  - Existing Anthropic thinking test moves from `provider/anthropic.rs`
    to `vendor::anthropic` (call site is now vendor-driven).
  - Add a test that `build()` composes: vendor detected via
    `pick_vendor`, transport chosen by `vendor.transport()`,
    thinking wired via `vendor.write_thinking`.

- **`mode::tui`** (light — this module is hard to unit-test):
  - `SettingsMenu` cycles values in order; save() called after each
    change (use a mock/injected saver).
  - Keybindings submenu: capture modal sets `app.bindings`; conflict
    prompt path returns unbound loser.

### 4.2 Implementation order (kept green each step)

1. `agent::thinking` — add serde impls + tests.
2. `src/keys.rs` — `ActionId`, `KeySpec`, `KeyBindings` + tests.
   Not yet wired into `interpret_key`.
3. `src/vendor/` — trait + 7 impls + `pick_vendor` + tests. Not yet

--lib -- --test-threads=1` remains the reliable-run command.

### 5.5 PI-parity deviations (documented, approved)

Both of these violate the "every feature must exist in PI first"
rule. Operator explicitly approved on 2026-08-13:

- **Keybindings editor**: PI has none. `defaultKeys` is hardcoded in
  `packages/coding-agent/src/core/keybindings.ts:73-76` (single action
  `app.thinking.cycle` on Shift+Tab). We ship a full editor because
  nanopi is TUI-only and BackTab/Shift+Tab is un-typeable in some
  terminal configs, so users need a rebind path.
- **`provider` config field**: PI derives provider from a model
  registry (`Model.provider` in `packages/ai/src/types.ts:34-72`,
  38 known ids). Nanopi has no such registry, so we expose an optional
  config string plus URL/model sniff.

### 5.6 Deferred to 0.9.4

- Verify Minimax `/anthropic` proxy accepts the exact
  `{thinking:{type:enabled,budget_tokens}}` shape without

- Model-swap vendor re-inference UI notice (when user
  `/model`-switches to a model whose vendor differs).
- Reasoning-token accounting (separate cost line for thinking

## Spec self-review

- **Placeholders**: none. Every "TODO 0.9.4" is a scoped follow-up
  (Qwen/Xiaomi/Minimax wire-format verification), not a spec gap.
- **Internal consistency**: single out-of-scope enumeration lives in
  the intro; §5.6 restates the same items under "Deferred to 0.9.4"
  without contradicting it. Every module named in §1.1 has a
  corresponding test bucket in §4.1. Every vendor named in §2.5's
  table has both a `write_thinking` sample and a `pick_vendor` test.
- **Scope**: 3 explicit deviations from PI parity (keybindings
  editor, `provider` config field, both in §5.5) and one implicit
  addition (`settings.toml` interaction section — a superset of PI's
  `settings.toml`) are all called out. No silent scope creep.
- **Ambiguity — decisions the implementer must confirm**:
  1. `KeySpec.follow` field — §2.3 says "drop if the impl doesn't
     need it". This is deliberately deferred to implementation but
     must be surfaced when the plan is written. Default recommendation
     during planning: **drop it** — nothing in this spec's tests
     requires it, and re-adding a field is cheap.
  2. Xiaomi `default_base_url` is left as "no default" in §2.5 (the
     xiaomimimo endpoint isn't stable). Implementer should confirm
     with the operator whether to leave it unset or hardcode the
     current known endpoint.
- **Coherence with existing code**: `src/settings.rs` (legacy hooks
  loader) coexists with the new `src/settings_toml.rs`. The dual-purpose
  `~/.nanopi/settings.toml` file is documented at §1.1 with the
  `#[serde(default)]` mitigation and reiterated at §5.2. No other
  silent overlaps.
