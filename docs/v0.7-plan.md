# nanopi v0.7 — UI/UX 全面升级

> 目标:把交互体验从"能用"提升到"顺手"。参考 PI(`~/workspace/pi`)和 Claude Code(`~/workspace/claude-code-haha-main`)的成熟做法,取实用的那部分,不追全副武装。

## 现状 (v0.6+ 已有)

- 默认交互 = rustyline 单行 + history + Ctrl-C/D 退出
- `--tui` = ratatui 四区(title / body / status / input),状态栏 1 行 hint
- Spinner braille 10 帧,turn 前显示
- Retry 429/5xx 指数退避
- Config.toml 统一入口

## v0.7 范围

分四层,由浅入深。**每层独立可交付,任意组合发布。**

---

### Tier 1 · 默认模式的最小增强(不改 UI paradigm)

现状:rustyline 单行 prompt,没有任何上下文提示。

- **1.1 Pre-turn status line**
  Turn 提交后、spinner 起来前打一条 dim 灰色状态:
  ```
  [claude-opus-4-7 · tokens 12.3k/200k · $0.08 · ~/nanopi · main]
  ```
  内容组件都是可选的,拿不到就跳过(比如非 git 目录不显示 branch)。

- **1.2 Post-turn footer**
  Turn 结束后打一条 dim 行:
  ```
  ↑ 340 ↓ 1204 · 8.2s · turn #3
  ```
  给用户一个自然的分节感。

- **1.3 Prompt 前缀带 session 短 id**
  改 `> ` 为 `[abc123] > ` — 一眼看出在哪个 session 里。

**代码影响**:`mode/interactive.rs` + 新 helper 模块 `render/status_line.rs`。零 crate 新增。~150 LOC。

---

### Tier 2 · `--tui` 状态栏三行化(对齐 PI footer)

现状:一行 hint "idle | Ctrl-C exit | ..."

改为 PI 风格三行:

```
─────────────────────────────────────────────────────
 ~/workspace/nanopi (main)          session abc123f0
 ↑ 12.3k  ↓ 4.5k  R 8.1k  W 320   $0.08   claude-opus-4-7
 45% context (auto)                   [Ctrl-C exit]
─────────────────────────────────────────────────────
```

- 行 1:cwd(带 `~` 折叠)+ git branch + session 短 id
- 行 2:token 用量 + cost + model
- 行 3:上下文百分比(>70% 黄,>90% 红,`(auto)` 后缀提示 auto-compaction 开启)+ 键位 hint

**代码影响**:`mode/tui.rs` 的 `ui()` 布局改 5 行(title / body / status ×3 / input);state 加 `token_totals: Usage`, `cost_usd: f64`;新 helper `render/status_line.rs` 复用 Tier 1 的组件。~200 LOC。

**依赖**:需要 model→price 映射(用于 cost 估算)。见 Tier 4.1。

---

### Tier 3 · `--tui` 输入框升级

现状:单行 bordered box,只处理 char/backspace/enter。

- **3.1 多行输入**
  Shift+Enter 换行,Enter 提交。行数动态,占屏高 20-30% 上限(参考 PI)。
  
- **3.2 Emacs 键位**
  Ctrl-A/E(行首/尾),Ctrl-K(删到行尾),Ctrl-W(删词),Ctrl-U(删整行),Ctrl-Y(yank 最近一次删除)。 
  Alt+B/F 词跳转。

- **3.3 简易 undo/redo**
  Ctrl-Z / Ctrl-Shift-Z,内存里一个 Vec<String> 快照栈,cap 10。

- **3.4 光标可见**
  当前 `> input_text` 不画光标。加个反色格子在 cursor 位置。

**代码影响**:`mode/tui.rs` 的 `App.input` 从 `String` 升级为 `TextBuffer { lines: Vec<String>, cursor_row, cursor_col, undo_stack, kill_ring }`。~300 LOC。新加 `render/text_buffer.rs` 单独测试。

**不做**:IME 支持(用户没提,复杂)、autocomplete(见 Tier 4.2)。

---

### Tier 4 · 交互富化

- **4.1 Cost & token tracking**
  加 `models.toml`(或内嵌 const)存 `model_id → (input$/1M, output$/1M, cache_read$/1M, cache_write$/1M)`。Agent 累加 turn Usage,session 里持久化。 
  文件例子:
  ```toml
  [models."claude-opus-4-7"]
  input  = 15.0
  output = 75.0
  cache_read = 1.5
  ```

- **4.2 Slash-command palette(仅 --tui)**
  输 `/` 弹一个下拉菜单列出已知命令(`/compact`, `/quit`, `/exit`, `/model`, `/reset`),↑↓ 选,Tab 补全,Esc 取消。空 `/` 显示所有;`/co` 过滤 fuzzy。

- **4.3 Tool panel 展开**
  当前 tool 结果只显示 `[bash → 97 bytes]`。加 Enter 键在 tool 行上展开完整输出(在 body 里插入内容块);再 Enter 折起。

- **4.4 更细的 spinner label**
  执行 bash 时 spinner 从 "thinking" 换成 `running bash: <cmd 前 40 字符…>`。 
  Read/Write/Edit 同理:`reading src/foo.rs`,`writing README.md`。

- **4.5 Markdown 轻渲染**
  Assistant 输出里的:`**bold**` → 反色/粗,`` `code` `` → 反色,fenced code block → 缩进块。 
  纯 stdout 版用 ANSI,`--tui` 版用 ratatui Style。

**代码影响**:分散在 agent/loop_(usage tracking)、render/(markdown)、mode/tui.rs(palette)。~500 LOC 总量,分子任务做。

## 推荐 v0.7 冲刺范围

**Sprint 1(必做,能立刻感知)**:Tier 1.1 + 1.2 + 2 全部 + 4.4  
预计 ~500 LOC + 20 单测。核心信息量翻倍,不改 paradigm。

**Sprint 2(体验加分)**:Tier 3.1 + 3.2 + 4.5(markdown)  
预计 ~400 LOC + 15 单测。输入不再痛苦,输出更好读。

**Sprint 3(打磨)**:Tier 4.1(cost tracking)+ 4.2(palette)  
预计 ~600 LOC + 30 单测。有量化反馈 + 命令发现。

**Sprint 4(可选)**:Tier 3.3(undo)+ 4.3(tool 展开)+ 3.4(光标)  
predicted "少量加分",按 v0.7 完成情况取舍。

---

## 明确不做

- 完整 IME / 输入法支持(复杂,非中文 CLI 环境优先级低)
- 图像 / 富文本渲染(超出 TUI 能力)
- 多窗格 / 分屏(nanopi 目标是 minimal)
- 主题系统(可选,v0.8)

---

## 度量成功

- v0.7 发布后,新用户 1 分钟内能看到:model、成本上限、当前 session id、token 用量趋势
- 长交互(20+ turns)不再依赖外部 `git status` / `du` 来知道自己在哪
- 输入错字的成本从"重打整行"降到"Ctrl-W 删词重来"
- 无需查文档就知道有哪些 slash 命令
