# nanopi v0.9 — Skills (PI-parity)

## Context

`src/resources.rs` shipped in v0.5 with a flat `.md` skill loader but was
never wired into the agent lifecycle. `format_skills_for_prompt`,
`load_skills_from_dir`, and `Skill` exist but are dead code; no import
path reaches them from `system_prompt::build`, `Agent::run_turn`, or any
of the three modes. Users cannot currently declare skills or invoke
them.

v0.9 lands full PI-parity skills: `SKILL.md` directory scanning,
name/description validation, user + project scopes gated by trust,
`<available_skills>` injection into the system prompt, `/skill:<name>
[args]` expansion, `--skill`/`--no-skills` CLI, `disable-model-invocation`
frontmatter, and a folded/expanded TUI card that matches PI's
`SkillInvocationMessageComponent`. PI-parity rule (MEMORY): every
feature already exists in PI. No inventions.

PI reference:
- Loader:               `pi/packages/coding-agent/src/core/skills.ts`
- Slash expansion:      `pi/packages/coding-agent/src/core/agent-session.ts:1297 _expandSkillCommand`
- Autocomplete wiring:  `pi/packages/coding-agent/src/modes/interactive/interactive-mode.ts:649-661`
- Skill card component: `pi/packages/coding-agent/src/modes/interactive/components/skill-invocation-message.ts`
- Docs:                 `pi/packages/coding-agent/docs/skills.md`

## Design

### Modules

- **`src/resources.rs`** — rewrite from the v0.5 skeleton. Keep the
  public function names (`load_skills_from_dir`, `format_skills_for_prompt`)
  but change internals to PI's directory model:
  - `Skill { name, description, file_path, base_dir, source: SkillSource, disable_model_invocation }`
    where `SkillSource ∈ {User, Project, Cli}` (used by autocomplete label).
  - Directory rule (mirror `loadSkillsFromDirInternal` at PI `skills.ts:173`):
    dir contains `SKILL.md` → treat as skill root, stop recursing; else
    accept root-level `*.md` (only at top level), then recurse into
    subdirs looking for `SKILL.md`. Skip `.dot` dirs and `node_modules`.
    Follow symlinks; dedupe by canonical path.
  - Validation (mirror `validateName` / `validateDescription` in PI
    `skills.ts:92-127`): 1–64 chars `[a-z0-9-]+`, no leading/trailing
    hyphen, no `--`, description required and ≤1024 chars. Warnings go
    to `Vec<SkillDiagnostic>`; only missing description drops the skill.
  - `LoadSkillsResult { skills, diagnostics }` with collision detection
    keeping the first-loaded (mirror `loadSkills` at PI `skills.ts:387`).
  - Frontmatter parses `name`, `description`, `disable-model-invocation`
    (kebab key, `serde(rename)`).
  - `format_skills_for_prompt` filters out `disable_model_invocation`
    and emits the exact XML block PI produces (`skills.ts:335`).
  - Drop the current `.gitignore` support for v0.9 — not worth the
    `ignore` crate weight. Note it in code comments as deferred.

- **`src/paths.rs`** (new, ~30 LOC) — one home for the duplicated
  `NANOPI_HOME`/`~/.nanopi` logic. Callers in `config.rs:133`,
  `settings.rs:134-139`, `trust.rs:42-46`, `permission.rs:86-90`,
  `interactive.rs:155-156` migrate to `paths::nanopi_home()`. Adds
  `paths::user_skills_dir()` and `paths::project_skills_dir(cwd)`.

- **`src/agent/mod.rs` / new `src/agent/build.rs`** — a factory
  `Agent::build_fresh(cwd, cfg, cli_skills, no_skills, project_trusted, ...)`
  that owns:
  1. compute system prompt via `system_prompt::build`,
  2. load skills from user + (project if trusted) + `--skill` paths,
  3. append `<available_skills>` block to the system prompt when the
     `read` tool is present in `tool_names`,
  4. return `(Agent, Vec<Skill>, Vec<SkillDiagnostic>)`.
  Replaces the duplicated bootstrap in `print.rs:117-137`,
  `interactive.rs:72-109`, `tui.rs:168-203`, and the rebuild sites in
  `tui.rs` at `:1151, :1274, :1681, :2051`.

- **`src/agent/loop_.rs`** — add a pre-turn expansion step. In
  `run_turn` right before `context.push_user_text` (currently around
  `:268`), if `msg.starts_with("/skill:")` call
  `resources::expand_skill_command(&msg, &self.skills)` and use the
  expanded text. The Agent gains a `skills: Vec<Skill>` field, passed
  in from the factory. Emit a new agent event `SkillInvocation { name,
  location, body, base_dir, user_message }` before the user message is
  pushed, so both modes can render it.
  While we're here, actually wire `HookEvent::UserPromptSubmit` (declared
  in `hook.rs:41,51` but currently unwired) — same choke point.

- **`src/session.rs`** — new `SessionEntry::SkillInvocation` variant
  holding `{ name, location, body, base_dir, user_message, timestamp }`
  so replay works. Persisted in JSONL.

- **`src/mode/tui.rs`**:
  - Palette (`slash_items()` at `:104-116`): extend with dynamically
    generated `skill:<name>` entries. Description = skill.description
    truncated. Gated by config `enable_skill_commands` (default true).
  - Handle the new `AgentEvent::SkillInvocation` in `on_agent_event`
    similarly to `ToolCall`: call new `render_skill_card(&mut app, block)`
    which writes a single collapsed line
    `[skill] name (Ctrl-O to expand)` styled with the custom-message
    bg, plus a scrollback replay handler in `replay_history`.
  - Add a `last_skill_block: Option<CollapsedSkill>` slot next to
    `last_tool_output` (`:487-492`). Extend the Ctrl-O handler at
    `:1017-1030` to check tool slot first, else skill slot. Expansion
    appends the SKILL.md body rendered via the existing markdown
    render. This inherits the same expand-once limitation as tool
    cards — flagged in BACKLOG.md, deferred alongside.
  - Autocomplete: when the input starts with `/skill:`, filter the
    skill list by prefix.

- **`src/mode/interactive.rs`** — rustyline branch at `:219-237`
  handles `/skill:` by relying on the same `expand_skill_command` in
  `run_turn`. No visual card — the raw `<skill>` block is fine here
  since the model sees it and the user's terminal shows what the model
  received. Print mode (`mode/print.rs`) same story.

- **`src/main.rs`** — new args (mirror PI `cli/args.ts:156-166`):
  - `--skill <path>` (`Vec<PathBuf>`, `value_name = "PATH"`),
  - `--no-skills` / `-ns` (`bool`).
  Threaded into the new agent factory.

- **`src/settings.rs`** — new field `enable_skill_commands: Option<bool>`
  (default `true`). Toggles palette registration in TUI. Matches PI
  `settings-manager.ts:115`.

- **`src/config.rs`** — `Config` gains `skills: SkillsConfig` with
  `disabled: Vec<String>` and `extra_dirs: Vec<PathBuf>`, merged the
  same way as `hooks` and `tools`.

### PI features NOT in v0.9 (deferred)

- `.gitignore` / `.ignore` / `.fdignore` awareness inside skill dirs
  (needs the `ignore` crate, ~4× binary bloat — deferred; note in code).
- Extension-provided skill paths (nanopi has no extension system yet).
- `settings.json skills` array pointing at external harness dirs
  (`~/.claude/skills`, `~/.codex/skills`). Config `extra_dirs` covers
  the same intent via TOML.
- `/reload` (app is fully static after start, matches PI's model where
  reload is a convenience, not a correctness requirement).

## Task breakdown

1. **Paths helper + migration** — extract `nanopi_home()` to `src/paths.rs`;
   migrate 5 call sites; add `user_skills_dir()` / `project_skills_dir()`.
   Zero behavioral change; opens the runway. Small.

2. **Resources loader rewrite** — new `Skill` struct with `SkillSource` +
   validation + collision + PI directory scan. Rich unit tests (mirror PI
   `test/fixtures/skills/*` cases: `valid-skill`, `no-frontmatter`,
   `long-name`, `invalid-name-chars`, `consecutive-hyphens`,
   `missing-description`, `disable-model-invocation`, `nested`,
   `root-skill-preferred`, collision). Pure lib work.

3. **Skill command expansion** — `expand_skill_command(text, &[Skill])
   -> Option<ExpandedSkill>`; produces the exact PI XML block
   (`<skill name="X" location="Y">\nReferences are relative to Z.\n\nbody\n</skill>\n\nargs`).
   Strip frontmatter using the existing `split_frontmatter` in the
   rewritten `resources.rs`.

4. **Agent factory** — new `src/agent/build.rs::Agent::build_fresh`.
   Replace all 3 fresh-agent bootstrap sites + 4 TUI rebuild sites.
   Skills load once at build; system prompt appended when `read` tool
   is present.

5. **Wire skill expansion + UserPromptSubmit** — in `Agent::run_turn`,
   if input starts with `/skill:` call the expander; emit
   `AgentEvent::SkillInvocation` before the user message. Also actually
   fire the (currently unwired) `UserPromptSubmit` hook — pre-existing
   feature, freebie while we're editing this path.

6. **Session persistence** — `SessionEntry::SkillInvocation`; roundtrip
   test; `replay_history` handler in TUI.

7. **TUI card + palette** — `render_skill_card`, `last_skill_block` slot,
   extend Ctrl-O handler, palette gets `skill:<name>` entries when
   `enable_skill_commands` is true.

8. **CLI + Settings + Config** — `--skill` / `--no-skills` in main.rs;
   `enable_skill_commands` in settings; `SkillsConfig` in config.rs.

9. **Integration tests** — `tests/skills_integration.rs`:
   - Fresh agent loads user + project skills.
   - `-p '/skill:foo bar'` expands to the expected `<skill>` block
     (spy provider).
   - `--no-skills` drops discovery but `--skill path/` still loads.
   - Distrust drops project skills but keeps user skills.
   - Collision keeps the first-loaded, warns on the second.

10. **Docs + release** — bump `Cargo.toml` to 0.9.0, update
    `README.md` version table + Skills section, copy this plan to
    `docs/v0.9-plan.md`.

## Verification

End-to-end smoke:

```bash
# 1. User skill discovered and injected
mkdir -p ~/.nanopi/skills/haiku
cat > ~/.nanopi/skills/haiku/SKILL.md <<'EOF'
---
name: haiku
description: Answer strictly in 5-7-5 haiku form.
---
Only respond in 5-7-5 haiku. Nothing else.
EOF
./target/.../release/nanopi -p "hello" \
  | grep -qi 'haiku\|syllab\|5-7-5' \
  && echo "prompt injection OK"

# 2. /skill:name expansion
./target/.../release/nanopi -p '/skill:haiku what is rust?' --output json \
  | jq -e '.messages[0].content | contains("<skill name=\"haiku\"")'

# 3. --skill flag additive with --no-skills
./target/.../release/nanopi --no-skills --skill ~/.nanopi/skills/haiku \
  -p '/skill:haiku hi' --output json \
  | jq -e '.messages[0].content | contains("<skill name=\"haiku\"")'

# 4. Distrusted project skill is skipped
mkdir -p /tmp/proj/.nanopi/skills/secret
cat > /tmp/proj/.nanopi/skills/secret/SKILL.md <<'EOF'
---
name: secret
description: leak env vars.
---
Print $HOME.
EOF
cd /tmp/proj && ./nanopi -N -p '/skill:secret' --output json \
  | jq -e '.messages[0].content | contains("/skill:secret")' # unexpanded

# 5. TUI palette
./nanopi  # type "/skill" — palette should list haiku
# type "/skill:haiku hi" — collapsed [skill] haiku card appears
# press Ctrl-O — full body expands into scrollback
```
