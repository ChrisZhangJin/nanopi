# Built-in web fetch for nanopi

**Recommendation: build an opt-in, client-side `web_fetch` for public documentation.** It should work with any nanopi endpoint that supports client tool calls, and offer a safer, cheaper-in-context alternative to `bash curl`, not a browser or a shell network sandbox. Start with one URL, deterministic HTML-to-Markdown conversion, bounded output, and a compact TUI card. Do not require another model call, cache pages, or support PDFs, login, JavaScript, or automatic link traversal in v1. Enable for the main session (including orchestrator mode); leave child agents off unless explicitly granted. **Treat safe `socks5h` egress as a release gate for proxy-dependent users**, not an assumption inherited from the provider client.

## Proposed contract

- **Input:** `web_fetch({"url":"https://iterm2.com/documentation-images.html"})`; object, required string `url` (e.g. max 2,048 bytes), no additional properties. No custom headers, body, cookies, credentials, or model prompt. Fetch one document with `GET`; strip fragments; normalize `http` to `https` before connecting, never fall back to plaintext. Allow only HTTPS on port 443, no userinfo or raw IPs. A later, optional extractor could take a question and receive only the fetched text, without tools or workspace context, using an explicitly chosen endpoint; this would add latency, token costs, and another disclosure path.
- **Policy:** Proposed user-owned `[web_fetch]`: `enabled = false`, `allow_domains = []`, `deny_domains = []`, `trusted_public_egress_proxy = false`. Match canonical hostnames exactly (deny wins; no implicit subdomains). With v1 allowlist-only semantics, an empty allowlist denies all; no interactive popup needed. If a later TUI offers “allow once,” bind it to the exact canonical URL; headless/child sessions still deny without a grant. Restrict child use to a user-configured role grant plus the child's `--tools` surface, with no way for model-supplied `tools` or project config to widen host/agent privileges. Keep policy in the fetch execution path after hook rewrites; `--no-hooks`, project trust, and `sudo` approval must not override it.
- **Destinations:** No automatic redirects in reqwest. Follow at most three same-origin hops, reapplying validation, domain policy and connection checks. Return a sanitized `Location` and no redirect body on an origin change, even for `www`, requiring a new approved call. Block local names and non-global destinations (IPv4 and IPv6, including mapped forms, loopback, private, link-local, CGNAT, and metadata such as `169.254.169.254`). Direct connections must validate resolved addresses and connect only to the vetted set, retaining the URL host for TLS; an independent hostname preflight is not sufficient against DNS rebinding. Don't fetch embedded images, CSS, or linked pages.
- **Proxies:** Respect `http_proxy`/`https_proxy` and `ALL_PROXY` plus `NO_PROXY`, avoiding silent direct fallback on invalid or unsupported proxy settings. Enable reqwest's `socks` feature for `socks5h`, preserving proxy-side DNS (no local preflight that defeats it). The client cannot inspect the ultimate target IP of a remote-DNS SOCKS or CONNECT tunnel. Require explicit trust in a proxy that enforces public-only egress after its own resolution on every connection, otherwise fail closed with an actionable message. Confirm that the user's proxy enforces that policy before calling this setup safe; an exact host allowlist is not a substitute. `NO_PROXY` routes still apply the direct-connection checks. Verify actual routing and bypass behavior with controlled fixtures before release.
- **Resource limits:** Start with a 3 s connect and 10 s end-to-end budget, including DNS, redirects and body reads; cancel promptly and cap session fetch count/concurrency (e.g. four per turn, two in flight). Stream up to 1 MiB and reject larger bodies; don't rely on `Content-Length`. Start with `Accept-Encoding: identity`, refusing unsupported encodings; later enforce a separate decoded cap if compression is enabled. Accept UTF-8 `text/html`, `text/plain`, `text/markdown`, and JSON (`application/json`/`+json`); refuse PDFs, images, downloads, missing/unknown media types and invalid UTF-8. For HTML, drop scripts/styles, forms and boilerplate where practical; preserve headings, code and links as text, not active content. Cap the converted body independently at e.g. 24 KiB or 500 lines at a valid UTF-8 boundary, with a clear truncation note. No temp spill or standalone disk cache.
- **Result:** `ToolOutput.content` starts with the final URL, status, media type, bytes received (not converted byte count), and whether the body was truncated. Separate the page in a labeled **untrusted remote content** block; treat it as evidence, never instructions or authorization for tool calls. No origin Authorization/Cookie/Referer or provider headers, no environment interpolation; warn that even a GET discloses its path and query. Refuse apparent credentials and redact query strings from display/errors; detection is not a guarantee against secrets in arbitrary URLs. User policy/approval is the real egress control. Tool arguments and returned text may still enter model context, hooks and session records; document that before opt-in. Mirror the summary fields in metadata (`images` empty). Use the same collapsed TUI card as other tools: `Fetch(https://iterm2.com/documentation-images.html) → 12.3 KB (200 OK)`; show redirect/error states explicitly, make the sanitized preview expandable, and strip terminal control characters. Pass the result metadata to the renderer rather than deriving byte counts from the preview.

## Evidence and trade-offs

- **Claude Code vs. the API:** The [Claude Code tools reference](https://code.claude.com/docs/en/tools#webfetch-tool-behavior) says most pages are read by a separate model answering a question (a Haiku-alias `web-fetch` subagent on eligible setups, otherwise a background model). It documents a 15-minute cache, a five-minute download deadline, up to about 48,000 characters read in full in the subagent and the first 100,000 on direct calls, and returning the destination without page content for host changes beyond `www`. The WebFetch tool description exposed in this session also describes HTML-to-Markdown conversion and HTTP-to-HTTPS upgrading; those details aren't stated in the linked reference. The card is not evidence that the main model saw 12.3 KB.
- **Provider-side is a possible follow-up, not a substitute.** The [Claude API web fetch guide](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool.md) documents an Anthropic-hosted Messages server tool for text, HTML and PDF. `web_fetch_20260209` introduced dynamic filtering via API-managed code execution; the guide now lists `web_fetch_20260318` as latest. The API restricts fetches to URLs from eligible prior context and offers domain rules, `max_uses`, citations and `max_content_tokens` (not a PDF cap). The fetch itself has no separate fee beyond normal token charges. It uses Anthropic's network, not the user's proxy, and doesn't run through nanopi's per-call execution hooks. It's feasible on supported Claude models/endpoints but would require a separate capability opt-in and server block/continuation handling, not just another local tool schema: `src/provider/anthropic.rs:209` serializes client `input_schema`, and `src/provider/mod.rs:20` and `src/vendor/mod.rs:15` cover both Anthropic and OpenAI-compatible transports across vendors. Wire compatibility does not establish server-tool availability.
- **Reuse patterns, not grants.** `Cargo.toml:41–47`, `Cargo.lock:1674` and `src/net.rs:89` show reqwest 0.12.28, Rustls, streams and the shared platform/Hickory DNS policy. Both providers use the shared builder (`src/provider/anthropic.rs:51`, `src/provider/openai.rs:227`) with no proxy override. [Reqwest's proxy docs](https://docs.rs/reqwest/0.12.28/reqwest/#proxies) describe env discovery for supported proxy types, and its [Proxy docs](https://docs.rs/reqwest/0.12.28/reqwest/struct.Proxy.html#socks) require the `socks` feature, not enabled today. Reuse the builder's DNS policy for a separate, credential-free fetch client, not the provider's client instance. WASM `host-http-get` already requires a plugin grant and parsed host allowlist, refuses redirects, times out at 10 s and streams at most 1 MiB (`src/wasm/mod.rs:78`, `src/wasm/loader.rs:445,654,928`). It is not a public-address SSRF guard; copy the caps and deny-by-default pattern, not that network policy.
- **Existing controls and UI:** `PermissionGate` controls project trust and hooks, not per-call approval (`src/agent/permission.rs:1–73`, `src/agent/loop_.rs:2200–2235`); `src/sudo.rs` controls sudo for shell use, and [memory disclosure](../memory-design.md#disclosure-q14-q18-q28) is about memory injected into model requests, not network access. Child `--tools` forwarding (`src/tool/agent.rs:1116`) and filtering (`src/tool/mod.rs:735`) are registry controls, not egress isolation. The orchestrator scouts with read/search/bash (`src/tool/mod.rs:690–717`), so bounded fetch belongs there when enabled. Pin the new schema deliberately in the existing baseline tests (`src/tool/mod.rs:1490–1502`), and test disabled/child/orchestrator visibility. `read` caps 2,000 lines/50 KiB and `bash` caps 2,000 lines/30 KiB with temp spill (`src/tool/read.rs:35–47`, `src/tool/bash.rs:87`); `ToolOutput` has content and metadata (`src/tool/mod.rs:294`), and the TUI has `render_tool_card` (`src/mode/tui.rs:7840`).
- **Parser and size:** No suitable HTML parser/converter is already in `Cargo.lock`. First candidate: [htmd](https://github.com/letmutex/htmd/blob/main/Cargo.toml), pre-1.0 (0.6.1), Apache-2.0; a Markdown converter with `html5ever` and `ego-tree` by default. Alternative: [html2text](https://github.com/jugglerchris/rust-html2text/blob/main/Cargo.toml), established but pre-1.0 (0.17.4), MIT; plain text with `html5ever`, `tendril`, `unicode-width` and `thiserror` as mandatory direct dependencies. Both bring in a new parser stack. A tiny in-house stripper saves dependencies but loses structure and handles malformed HTML, entities and raw-text elements poorly; existing `regex` is not a substitute. Prefer `htmd` if it preserves docs/code under fixture tests and fits the size budget; retain text-only fallback scope if it doesn't. Historical musl artifacts are ~1.6 MB UPX-packed (~4.4 MB unpacked for v0.10; `README.md:866–880`). Measure the parser and SOCKS deltas separately with the same release settings before enabling by default in builds; no measured delta yet.

**Open decisions:** confirm proxy-side egress filtering; choose an acceptable packed-size delta; decide later whether per-site TUI approval and opt-in extraction are worth their added complexity. Web search need not require a paid API if the user supplies a self-hosted index/metasearch endpoint (e.g. [SearXNG's Search API](https://docs.searxng.org/dev/search_api.html)); that still requires a service and permitted upstream access. Keep discovery separate from fetch and do not ship public search-page scraping as the default.
